==============================================================================
BASIC++ v6.5.2 Internals and Architecture
==============================================================================

1. EXECUTION PIPELINE

BASIC++ processes source code through a modular pipeline: Lexer, Parser, AST
Evaluator, Bytecode VM (optional), and Runtime Engine. In interpreted
execution, tokens and parse nodes are processed iteratively: source code text
remains canonical in memory, allowing dynamic line editing and program
modifications (RENUM, AUTO, DELETE) with deterministic execution semantics.

The execution sequence for a statement:
1. The VM retrieves the target line from ProgramStore (a sorted index of line
   numbers).
2. The lexer (LexerContext) scans source text on demand, producing BppToken
   records.
3. The parser dispatches statement execution through the registration table
   (StmtRegistry).
4. The statement handler evaluates expressions via the linear evaluator or
   AST evaluator, interacts with variables through VariableContext, and
   executes I/O via VDevContext.
5. The handler returns a BppError record. A zero code advances execution; a
   non-zero code triggers active ON ERROR GOTO traps or displays runtime
   diagnostics.

2. THE NON-RECURSIVE VM ARCHITECTURE

The virtual machine operates without recursive host stack dependency. All
execution frames, loop contexts, and evaluation state reside in pre-allocated
heap and arena pools. Deeply nested program structures (hundreds of GOSUB
invocations, complex loops, or nested expressions) execute without risk of C
host stack overflow.

The VMContext (engine/include/vm/vm.h, engine/src/vm/context.c) encapsulates
complete execution state:
* MemoryContext: Program text storage and temporary scratch allocator.
* StringContext: Managed string heap with automatic garbage collection.
* VariableContext: Named variable table and scope frames.
* ArrayContext: Multidimensional array storage and matrix algebra engine.
* VDevContext: Pluggable virtual device bus for all peripheral I/O.
* FileContext: File channels and record buffer sector tables.
* VConContext: Virtual console terminal emulation (VT100, ANSI colors).
* VfsContext: Virtual filesystem mounting abstraction.
* VNetContext: Networking sockets, FujiNet, and protocol handlers.
* BiosContext: BIOS hardware virtualization and interrupt vectors.
* StmtRegistry: Intrinsic statement handler dispatch table.
* TryStack: Structured exception handling stack.

Control-flow constructs utilize dedicated execution stacks: GosubStack,
ForStack, WhileStack, DoStack, and SelectStack. Separate stacks guarantee that
NEXT checks only the active FOR loop, RETURN validates only GOSUB frames, and
WEND validates only WHILE blocks.

3. THE LEXER

The lexer (engine/include/lexer/lexer.h, engine/src/lexer/lexer.c)
scans source lines on demand. Tokens (BppToken) encapsulate:
* Token type (BppTokenType): Keyword, identifier, literal number, string,
  delimiter, operator.
* Keyword ID (BppKeywordId): Enumerated token identifier for constant-time
  dispatch.
* Value payload: Numeric double, string pointer slice, or symbol identifier.
* Source coordinates: Line number and column offset for accurate error
  reporting.

4. DUAL EVALUATION ENGINES

BASIC++ incorporates two complementary expression evaluators:
1. Linear VM Evaluator (eval_expression, eval_execute_op): An iterative
   operator-precedence evaluator optimized for high-speed sequential
   execution, vintage branchless arithmetic, and low memory overhead.
2. Recursive AST Evaluator (eval_ast_evaluate, eval_ast_stmt_assign): A
   tree-walking evaluator utilized for complex algebraic collections, typed
   UDT records, and compiler code generation targets.

Both evaluators enforce the Hardware Division-by-Zero Guard: integer division
(\) and modulo (MOD) verify that divisors are non-zero before invoking
hardware division instructions, eliminating CPU traps (0xC0000094).

5. STRING HEAP & GARBAGE COLLECTION

Strings in BASIC++ use descriptor handles referencing immutable byte slices.
String allocation occurs within the dedicated StringHeap. When heap
utilization approaches capacity, the runtime executes a compacting garbage
collection pass: active string descriptors in the variable table and fielded
file buffers are traced, unreferenced strings are reclaimed, and active
strings are compacted to eliminate external fragmentation.

6. MEMORY ARENAS & CERTIFIED ALLOCATION

In accordance with ISO C17 certified allocation models, the engine avoids
unmanaged malloc and free calls during execution. Transient AST nodes use
linear arena allocators (RuntimeArena) that reset after statement execution,
while persistent state resides in bounded pools.
