BASIC++ v6.5.2 Memory Maps & Partition Architecture
==============================================================================

1. MEMORY ARCHITECTURE OVERVIEW

BASIC++ manages memory through certified allocation models that divide process
memory into four dedicated regions: Program Memory, Variable Memory, String
Heap, and Scratch Area. Total pool sizing and stack limits are configured per
build profile in engine/include/types/config.h.

    +------------------------------------------+  0x00000000
    |  Program Memory                          |  Line-numbered source text
    +------------------------------------------+
    |  Variable Memory                         |  Variables, arrays, UDTs
    +------------------------------------------+
    |  String Heap                             |  Managed string descriptors
    +------------------------------------------+
    |  Scratch Area                            |  Evaluator scratch stacks
    +------------------------------------------+

2. MODERN 64-BIT DESKTOP PROFILE (baspp)

The flagship desktop edition allocates 640 MB (671088640L bytes) by default:

Region           Allocation  Responsibilities
------------------------------------------------------------------------------
Program Memory   128 MB      Source text, ProgramStore sorted index
Variable Memory  128 MB      Variables, array elements, UDT instances
String Heap      256 MB      Managed string descriptors, compacting GC
Scratch Area     128 MB      Expression stacks, statement working buffers

Stack depths: 1023 (Gosub, For, While, Do, Select, Sub), TryStack 255.
Limits: 8192 named variables, 4096 DIM arrays, 4,194,304 array elements, 256
user-defined functions.

3. LITE INTERACTIVE PROFILE (bpp)

The lite terminal REPL allocates 384 MB (402653184L bytes) total:
* Program Memory: 64 MB
* Variable Memory: 64 MB
* String Heap: 192 MB
* Scratch Area: 64 MB

Stack depths: 1023. Limits: 8192 named variables, 4096 DIM arrays, 4,194,304
array elements.

4. BATCH SCRIPT RUNNER PROFILE (bs)

The headless batch runner allocates 64 MB (67108864L bytes) optimized for
automation:
* Program Memory: 16 MB
* Variable Memory: 16 MB
* String Heap: 16 MB
* Scratch Area: 16 MB

5. MICROCONTROLLER & IOT PROFILE (iot)

The embedded micro-REPL allocates a compact 2 MB (2097152L bytes) static pool:
* Program Memory: 512 KB
* Variable Memory: 512 KB
* String Heap: 512 KB
* Scratch Area: 512 KB

6. FREEDOS 16-BIT PROFILE

The FreeDOS real-mode profile fits within 640 KB conventional RAM:
* Program Memory: 32 KB
* Variable Memory: 16 KB
* String Heap: 16 KB
* Scratch Area: 8 KB

Stack depths: 63. Limits: 128 named variables, 32 DIM arrays, 2048 elements,
16 user functions.

7. EMBEDDED CONSTRAINED PROFILE

For resource-restricted microcontrollers (32 KB RAM / 128 KB flash):
* Program Memory: 8 KB
* Variable Memory: 4 KB
* String Heap: 4 KB
* Scratch Area: 2 KB

Total runtime footprint: ~18 KB RAM. Stack depths: 31. Limits: 64 named
variables, 16 DIM arrays, 512 elements.

8. MEMORY INTROSPECTION FUNCTIONS

* FRE(0): Returns free bytes remaining in the string heap.
* FRE(-1): Returns largest contiguous free memory block in string arena.
* FRE(-2): Returns available bytes in variable memory partition.
* MEMMAP$: System variable returning active memory profile name ("MODERN",
  "LITE", "BATCH", "IOT", "FREEDOS").
* INFO: Interactive command displaying current allocations and usage.

9. COMPILE-TIME PREPROCESSOR DEFINES

Memory profiles are configured via preprocessor definitions in
engine/include/types/config.h:
* BASIC_DEFAULT_PROG_MEM: Program memory size in bytes.
* BASIC_DEFAULT_VAR_MEM: Variable memory size in bytes.
* BASIC_DEFAULT_STR_MEM: String heap size in bytes.
* BASIC_DEFAULT_SCRATCH_MEM: Scratch area size in bytes.
* BASIC_DEFAULT_MAX_VARS: Maximum named variable count.
* BASIC_DEFAULT_STACK_DEPTH: Control-flow stack depth ceiling.
* BASIC_DEFAULT_MAX_DIM: Maximum active DIM array descriptors.
* BASIC_DEFAULT_MAX_ELEMENTS: Maximum total elements per array.

10. DYNAMIC ARENA SCALING

On modern desktop platforms, the announced pool size represents the default
reserve. Memory arenas can expand dynamically if required by large datasets.
The CLEAR [bytes] statement allows explicit reallocation of the string arena
at runtime.
