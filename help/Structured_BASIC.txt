======================================================================
  BASIC++ V6.5.2 STRUCTURED BASIC PROGRAMMING
======================================================================


======================================================================
  1. BEYOND LINE NUMBERS
======================================================================

While BASIC++ supports traditional line-numbered GOTO/GOSUB programming, it also provides structured control-flow constructs that reduce or eliminate the need for GOTO. Structured programs are easier to read, maintain, and debug. All control structures in BASIC++ are implemented as separate stack types in the VM, ensuring precise error messages when structures are mismatched.


======================================================================
  2. BLOCK IF/THEN/ELSE
======================================================================

The block IF structure allows multi-line conditional execution with ELSEIF and ELSE branches:

10 IF Score >= 90 THEN
20   Grade$ = "A"
30   PRINT "Excellent!"
40 ELSEIF Score >= 80 THEN
50   Grade$ = "B"
60   PRINT "Good"
70 ELSEIF Score >= 70 THEN
80   Grade$ = "C"
90   PRINT "Average"
100 ELSE
110   Grade$ = "F"
120   PRINT "Below average"
130 END IF

The block IF is distinct from the single-line IF. The block form is recognized when THEN appears at the end of the line with no statement following it. Every block IF must have a matching END IF.


======================================================================
  3. SELECT CASE
======================================================================

SELECT CASE evaluates an expression once and matches it against CASE clauses in sequence:

10 SELECT CASE Month
20   CASE 1, 3, 5, 7, 8, 10, 12
30     Days = 31
40   CASE 4, 6, 9, 11
50     Days = 30
60   CASE 2
70     IF Year MOD 4 = 0 THEN Days = 29 ELSE Days = 28
80   CASE ELSE
90     PRINT "Invalid month"
100 END SELECT

CASE values can be single values (CASE 5), lists (CASE 1, 3, 5), ranges (CASE 1 TO 10), or comparisons (CASE IS > 100). CASE ELSE handles unmatched values. Only the first matching CASE block executes; there is no fall-through between cases.


======================================================================
  4. FOR/NEXT LOOPS
======================================================================

FOR/NEXT provides counted iteration:

10 FOR I = 1 TO 10
20   PRINT I; I * I
30 NEXT I

The STEP clause specifies the increment (default 1): FOR I = 10 TO 0 STEP -1. The BY keyword is an alternative spelling inherited from Tymshare Super BASIC: FOR I = 1 TO 100 BY 5.

The loop variable, limit, and step are evaluated once at the FOR statement and stored in a BppForFrame on the ForStack. The limit and step are not re-evaluated on each iteration.

EXIT FOR leaves the current FOR loop immediately, continuing at the statement after the matching NEXT.

Nested FOR loops must have matching NEXT statements in reverse order. NEXT without a variable closes the innermost FOR. NEXT with a variable closes that specific FOR and any inner FORs still open:

10 FOR I = 1 TO 5
20   FOR J = 1 TO 5
30     PRINT I * J;
40   NEXT J
50   PRINT
60 NEXT I


======================================================================
  5. WHILE/WEND LOOPS
======================================================================

WHILE/WEND repeats a block while a condition is true:

10 X = 1
20 WHILE X <= 100
30   PRINT X
40   X = X * 2
50 WEND

The condition is tested at the top of each iteration. If the condition is false on entry, the body never executes. Each WHILE pushes a BppWhileFrame onto the WhileStack. WEND pops the frame and loops back to the WHILE line.


======================================================================
  6. DO/LOOP
======================================================================

DO/LOOP provides four variants of conditional looping:

Pre-test with WHILE (identical behavior to WHILE/WEND):
10 DO WHILE X > 0
20   X = X - 1
30 LOOP

Pre-test with UNTIL (loop while condition is false):
10 DO UNTIL X = 0
20   X = X - 1
30 LOOP

Post-test with WHILE (body always executes at least once):
10 DO
20   INPUT "Enter number (0 to quit): "; X
30 LOOP WHILE X <> 0

Post-test with UNTIL (body always executes at least once):
10 DO
20   INPUT "Enter number (0 to quit): "; X
30 LOOP UNTIL X = 0

EXIT DO leaves the current DO loop immediately.


======================================================================
  7. NAMED PROCEDURES (SUB/FUNCTION)
======================================================================

SUB and FUNCTION replace GOSUB for reusable code blocks with proper parameter passing and local variables. See the Subroutines and Functions guide for full details.


======================================================================
  8. STRUCTURED ERROR HANDLING (TRY/CATCH)
======================================================================

TRY/CATCH provides structured error handling that replaces the global ON ERROR GOTO approach for localized error recovery:

10 TRY
20   OPEN "CONFIG.TXT" FOR INPUT AS #1
30   INPUT #1, Setting$
40   CLOSE #1
50 CATCH
60   Setting$ = "DEFAULT"
70   PRINT "Using default settings"
80 END TRY

Each TRY block is self-contained. Errors inside the TRY transfer to its own CATCH. After the CATCH completes, execution continues normally after END TRY.


======================================================================
  9. POSTFIX MODIFIERS
======================================================================

BASIC++ supports postfix conditional modifiers that place the condition after the statement:

10 PRINT "Positive" IF X > 0
20 PRINT "Not empty" UNLESS A$ = ""
30 PRINT "In range" IF X > 0 IF X < 100

UNLESS is a negated IF: PRINT "ok" UNLESS error is equivalent to IF NOT error THEN PRINT "ok".

Multiple postfix modifiers evaluate right-to-left. In line 30, IF X < 100 is evaluated first. If true, IF X > 0 is evaluated. If both are true, the PRINT executes. Any false condition aborts the statement.


======================================================================
  10. ELIMINATING GOTO
======================================================================

Common GOTO patterns and their structured replacements:

| GOTO Pattern | Structured Replacement |
|-------------|----------------------|
| IF cond GOTO line | IF cond THEN ... END IF |
| GOTO loop_start | WHILE/WEND or DO/LOOP |
| ON n GOTO list | SELECT CASE |
| GOTO error_handler | TRY/CATCH |
| GOSUB subroutine | SUB/FUNCTION with CALL |

GOTO remains available for situations where it is genuinely the clearest approach, such as breaking out of deeply nested structures or implementing state machines. BASIC++ does not deprecate GOTO.
