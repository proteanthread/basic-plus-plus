
BASIC++ Universal Hybrid Dialect Architecture
=============================================


1. The Unified Keyword Space
----------------------------

Historically, BASIC++ attempted to strictly separate keyword availability into distinct "dialects" (such as GW-BASIC, QBasic, TRS-80, Sinclair, etc.). Keywords were bound to DFLAG_ bitmasks, and attempting to use a keyword from dialect A while in dialect B would result in a syntax error.

In modern BASIC++, all keywords are universally available at all times. The DFLAG_ isolation system has been entirely removed.


What This Means For You:
~~~~~~~~~~~~~~~~~~~~~~~~
 *No DIALECT Switching Needed:** You do not need to invoke the DIALECT or DIALECT$ commands anymore.
* Hybrid Programs Are The Norm: You can freely write code that mixes GW-BASIC's DEF FN, Sinclair's PAUSE, QBasic's DO...LOOP, and SuperBASIC's REPeat.
 Zero Configuration: BASIC++ boots directly into its universal mode.


2. Resolving Conflicts (The GW-BASIC Priority Rule)
---------------------------------------------------

Because all keywords share a single namespace, conflicts can arise between dialects that implement the same concept differently.

The Golden Rule: If a feature, keyword, or function conflicts with GW-BASIC or QBasic behavior, the GW-BASIC / QBasic behavior takes absolute priority.*

This ensures that the vast majority of legacy MS-DOS BASIC software continues to run flawlessly. If a Sinclair or Atari specific function behaves exactly like a GW-BASIC keyword, the GW-BASIC implementation handles it.


3. Structural Control Flow Modernization
----------------------------------------

Because control structures from different dialects are now mixed, BASIC++'s parser natively understands both historical statement modifiers and block structures.

For example, IF...THEN...ELSE has been unified. The parser seamlessly handles:
1. **Single-line MS-BASIC IF:** IF X = 1 THEN PRINT "YES" ELSE PRINT "NO"
2. **QBasic Block IF:** IF X = 1 THEN ... ELSE ... END IF
3. SuperBASIC Modifiers: The UNLESS keyword (an inverse IF) works anywhere IF does: UNLESS X = 1 THEN PRINT "NO"

The internal pi_parse_if and pi_parse_unless routing now shares a generalized parse_conditional_flow engine, ensuring consistent runtime stack behavior regardless of which dialect's keyword you chose to invoke.


4. Recovering Legacy Compatibility
----------------------------------

Because BASIC++ is a superset of all historical functionality, existing .BAS files may occasionally trip over new universal keywords that were formerly valid variable names.

* Example: OVER was a command in Sinclair BASIC but might be a variable OVER = 1 in an MS-DOS program.
* Resolution: To prevent syntax collision, simply rename the conflicting variable in the .BAS file using an underscore. Change OVER = 1 to R_OVER = 1 or OVER_VAR = 1.

*Note: All distributed .BAS files must include a header comment detailing these potential keyword conflicts and offering the underscore renaming solution.*


5. Security and Environment
---------------------------

The virtual subsystem defaults to OPEN security (fully unrestricted file and network I/O) unless overridden by a basicpp.cfg file. This means the hybrid keyword space has immediate, out-of-the-box access to the underlying OS through standard QBasic OPEN statements or advanced virtual device VDEV assignments.
