CREATING YOUR OWN DIALECTS
===========================
Version 4.0.1

BASIC++ has a configurable dialect engine that controls which
keywords are accepted, how variables work, what syntax rules
apply, and how the interpreter behaves.  This guide is a
complete tutorial for creating your own dialects — from a
minimal teaching language to a full-featured custom scripting
language.

Whether you want to build a domain-specific language for
scientific computing, a restricted teaching dialect, a retro-
computing emulation, or an entirely new BASIC variant, this
manual shows you how.

        PART I: UNDERSTANDING THE DIALECT ENGINE

=====================================================================


=====================================================================
1. WHAT IS A DIALECT?
=====================================================================

A dialect defines a complete personality for the BASIC++
interpreter.  When you switch dialects, you change:

  - Which keywords are accepted or rejected
  - How variables are named (A-Z only, or long names)
  - Whether line numbers are required
  - Whether THEN is required after IF
  - Whether LET can be omitted
  - Which features are available (arrays, strings, floats)
  - How PRINT formats output (zone widths, separators)
  - What the ready prompt looks like ("Ok", "READY.", ">")
  - Which functions are available (math, string, I/O)
  - How errors are reported
  - What the statement separator character is (: or ;)
  - How the not-equal operator is written (<> or #)

Think of a dialect as a "personality pack" for the interpreter.
The same parsing and execution engine powers all dialects —
only the configuration changes.


=====================================================================
2. THE DIALECTCONFIG STRUCTURE (FIELD BY FIELD)
=====================================================================

Every dialect is defined by a single C structure:

  typedef struct DialectConfig {
      DialectId   id;                 /* enum index */
      const char name;               / "GW-BASIC" */
      char        stmt_separator;     /* ':' or ';' */
      int         has_then_keyword;   /* IF requires THEN? */
      int         has_let_optional;   /* Can omit LET? */
      int         has_for_next;       /* FOR/NEXT loops? */
      int         has_string_vars;    /* String variables (A$)? */
      int         has_print_hash;     /* PRINT #n formatting? */
      int         has_array_at;       /* @(i) array syntax? */
      int         has_rnd_function;   /* RND() available? */
      int         has_abs_function;   /* ABS() available? */
      int         has_size_function;  /* SIZE available? */
      int         max_line_number;    /* 32767, 65529, 99999 */
      int         not_eq_is_hash;     /* # means <> ? */
      int         has_data_read;      /* DATA/READ/RESTORE? */
      int         has_while_wend;     /* WHILE/WEND loops? */
      int         has_do_loop;        /* DO/LOOP loops? */
      int         has_extended_vars;  /* Long variable names? */
      int         has_merge_chain;    /* MERGE/CHAIN commands? */
      int         has_float;          /* Floating-point? */
      int         has_dim_arrays;     /* DIM arrays? */
      int         has_string_functions; /* String funcs? */
      const char ready_prompt;       / "Ok", "READY", etc. */
      int         print_zone_width;   /* 8, 10, 14, 16 */
      int         has_on_error;       /* ON ERROR GOTO? */
      int         has_cls;            /* CLS command? */
      int         has_tron_troff;     /* TRON/TROFF debug? */
      const char short_name;         / "GWBS", 4 chars */
      unsigned int dialect_flag;      /* DFLAG_GWBS bitmask */
  } DialectConfig;

Each field is a simple flag or value.  The parser and runtime
query these fields to determine behavior.  No if/else chains
are needed in the parser — it just reads the config.

=====================================================================
4. DIALECT BITMASK SYSTEM (DFLAG_*)
=====================================================================

Every keyword in the lexer is tagged with a bitmask indicating
which dialects support it.  The bitmask is a 16-bit unsigned:

  DFLAG_PATB   bit 0    Palo Alto Tiny BASIC
  DFLAG_TRS1   bit 1    TRS-80 Level I
  DFLAG_TRS2   bit 2    TRS-80 Level II
  DFLAG_GWBS   bit 3    GW-BASIC
  DFLAG_EC55   bit 4    ECMA-55
  DFLAG_E116   bit 5    ECMA-116
  DFLAG_QBAS   bit 6    QBasic
  DFLAG_AINT   bit 7    Apple Integer
  DFLAG_ASFT   bit 8    AppleSoft
  DFLAG_ATRI   bit 9    Atari BASIC
  DFLAG_C64B   bit 10   Commodore BASIC
  DFLAG_COCO   bit 11   Tandy CoCo
  DFLAG_ALL    0xFFFF   All dialects (BASIC++ native)

  Convenience macros:
  DFLAG_MSBASIC  = TRS2|GWBS|QBAS|ASFT|C64B|COCO  (Microsoft family)
  DFLAG_MSALL    = TRS1|MSBASIC  (all Microsoft including Level I)
  DFLAG_STRUCT   = GWBS|QBAS|E116  (structured BASICs)
  DFLAG_GWQB     = GWBS|QBAS  (GW/QBasic pair)

  Example keyword bitmask:
    WHILE: DFLAG_STRUCT = GWBS|QBAS|E116
    This means WHILE is native to GW-BASIC, QBasic, and ECMA-116.
    In strict mode, other dialects reject WHILE.


=====================================================================
5. STRICT MODE VS UNION MODE
=====================================================================

  UNION MODE (default): All keywords from ALL dialects are
  accepted.  A PATB program can use WHILE.  A C64B program
  can use SELECT CASE.  This is the "BASIC++ is the union
  of all dialects" philosophy.

  STRICT MODE: Only keywords belonging to the active dialect's
  bitmask are accepted.  Enable with:
    OPTION STRICT
  Disable with:
    OPTION STRICT OFF

  In strict mode:
    DIALECT "TRS1"
    OPTION STRICT
    WHILE 1          ' ERROR! WHILE not in TRS-80 Level I
    WEND

  The check happens in dialect_keyword_allowed():
    int dialect_keyword_allowed(KeywordId kw)
    {
        if (!strict_mode) return 1;       /* union: allow all */
        kw_flags = lexer_get_keyword_flags(kw);
        if (kw_flags == DFLAG_ALL) return 1;  /* native: always OK */
        return (kw_flags & active_dialect->dialect_flag) ? 1 : 0;
    }


=====================================================================
6. HOW THE PARSER USES DIALECT CONFIG
=====================================================================

The parser queries the active DialectConfig at key points:

  IF statement:
    if (dialect->has_then_keyword) {
        /* expect THEN token after condition */
    } else {
        /* PATB: IF condition statement (no THEN) */
    }

  Variable assignment:
    if (dialect->has_let_optional) {
        /* A = 5 is valid without LET */
    } else {
        /* ECMA-55: LET A = 5 required */
    }

  Statement separator:
    if (ch == dialect->stmt_separator) {
        /* start next statement on same line */
    }
    /* PATB: ; separates.  All others: : separates. */

  Not-equal operator:
    if (dialect->not_eq_is_hash) {
        /* PATB: # means <> */
    } else {
        /* all others: <> means not-equal */
    }

  Line numbers:
    if (line_num > dialect->max_line_number) {
        /* error: line number too large for this dialect */
    }


=====================================================================
7. HOW THE RUNTIME USES DIALECT CONFIG
=====================================================================

The runtime queries dialect config for behavior:

  PRINT zone width:
    col = (col / dialect->print_zone_width + 1)
          * dialect->print_zone_width;

  Ready prompt:
    printf("%s\n", dialect_get_ready_prompt());

  Feature gating:
    if (!dialect->has_float) {
        /* integer-only arithmetic mode */
    }
    if (!dialect->has_string_vars) {
        /* reject A$ = "hello" */
    }
    if (!dialect->has_dim_arrays) {
        /* reject DIM A(10) */
    }

8. TUTORIAL 1: MINIMAL TEACHING BASIC
=====================================================================

GOAL: A simplified BASIC for teaching programming fundamentals.
Only core constructs, no advanced features, clear error messages.

  Name: "Teach BASIC"
  Code: "TEBA"
  Philosophy: If a student can master this subset, they
  understand the fundamentals of structured programming.

STEP 1: Define the configuration

  In dialect.h, add to DialectId enum:
    DIALECT_TEACH,        /* Teaching BASIC */

  In dialect.c, add the config:

  {
      DIALECT_TEACH,
      "Teach BASIC",
      ':',    /* stmt_separator */
      1,      /* has_then_keyword: YES */
      1,      /* has_let_optional: YES (simpler for beginners) */
      1,      /* has_for_next: YES */
      1,      /* has_string_vars: YES (A$) */
      0,      /* has_print_hash: NO (too confusing) */
      0,      /* has_array_at: NO */
      1,      /* has_rnd: YES (for games) */
      1,      /* has_abs: YES */
      0,      /* has_size: NO */
      9999,   /* max_line_number (4 digits, simpler) */
      0,      /* not_eq_is_hash: NO (use <>) */
      1,      /* has_data_read: YES */
      1,      /* has_while_wend: YES (structured!) */
      0,      /* has_do_loop: NO (WHILE is enough) */
      0,      /* has_extended_vars: NO (A-Z only) */
      0,      /* has_merge_chain: NO (single-file only) */
      1,      /* has_float: YES */
      1,      /* has_dim_arrays: YES */
      1,      /* has_string_functions: YES */
      "READY> ",  /* ready_prompt (clear, inviting) */
      14,     /* print_zone_width */
      0,      /* has_on_error: NO (let errors show) */
      1,      /* has_cls: YES */
      0,      /* has_tron_troff: NO */
      "TEBA", /* short_name */
      (1u << 12)  /* dialect_flag: bit 12 (first user bit) */
  },

STEP 2: Set keyword bitmask on allowed keywords

  In the lexer's keyword table, add the TEBA flag to:
    PRINT, INPUT, LET, IF, THEN, ELSE, GOTO, GOSUB, RETURN,
    FOR, TO, STEP, NEXT, WHILE, WEND, DIM, REM, END,
    CLS, DATA, READ, RESTORE

  Do NOT add:
    COMPILE, CHAIN, SYSTEM, EXEC, SECURITY, MODULE,
    SELECT, CASE, SUB, FUNCTION, ON ERROR, SWAP, MERGE

STEP 3: Register in dialect.c

  Update DIALECT_COUNT to include the new entry.

STEP 4: Test

  DIALECT "TEBA"
  OPTION STRICT
  10 CLS
  20 PRINT "Hello! What is your name?"
  30 INPUT N$
  40 PRINT "Nice to meet you, "; N$; "!"
  50 FOR I = 1 TO 5
  60   PRINT I; " squared is "; I*I
  70 NEXT I
  80 END
  RUN

  Now test rejection:
  90 COMPILE "test.c"     ' Should error in strict mode

GOAL: A math-heavy dialect with enhanced numeric precision,

  Name: "SciBasic"
  Code: "SCIB"

  Key features:
  - All math functions always available

STEP 1: Config

  {
      DIALECT_SCIENTIFIC,
      "SciBasic",
      ':',  1, 1, 1, 1, 0, 0, 1, 1, 0, 99999, 0,
      1, 1, 1, 1, 1,
      1, 1, 1,
      "sci> ",  14, 1, 1, 1, "SCIB",
      (1u << 13)

STEP 2: Register a companion module

  The dialect module registers extra math functions:

  static int scibasic_init(void *rt)
  {
      /* Register extended math functions */
      static const FunctionEntry sci_funcs[] = {
          {"LOG10", KW_COUNT, FCAT_MATH, FRET_FLOAT,
           1,1, FSAFE_PURE, 0, fn_log10, "Log base 10"},
          {"LOG2",  KW_COUNT, FCAT_MATH, FRET_FLOAT,
           1,1, FSAFE_PURE, 0, fn_log2, "Log base 2"},
          {"HYPOT", KW_COUNT, FCAT_MATH, FRET_FLOAT,
           2,2, FSAFE_PURE, 0, fn_hypot, "Hypotenuse"},
          {"POW",   KW_COUNT, FCAT_MATH, FRET_FLOAT,
           2,2, FSAFE_PURE, 0, fn_pow, "Power function"},
          {"CEIL",  KW_COUNT, FCAT_MATH, FRET_FLOAT,
           1,1, FSAFE_PURE, 0, fn_ceil, "Ceiling"},
          {"FLOOR", KW_COUNT, FCAT_MATH, FRET_FLOAT,
           1,1, FSAFE_PURE, 0, fn_floor, "Floor"},
          {"ROUND", KW_COUNT, FCAT_MATH, FRET_FLOAT,
           1,2, FSAFE_PURE, 0, fn_round, "Round"},
      };
      int i;
      (void)rt;
      for (i = 0; i < 7; i++)
          funcreg_register(&sci_funcs[i]);
      return 0;
  }

STEP 3: Usage

  DIALECT "SCIB"
  MODULE "MATHEXT"
  10 DIM MATRIX(4, 4)
  20 FOR ROW = 1 TO 4
  30   FOR COL = 1 TO 4
  40     MATRIX(ROW, COL) = RND(100)
  50   NEXT COL
  60 NEXT ROW
  70 TOTAL = 0
  80 FOR I = 1 TO 4
  90   TOTAL = TOTAL + MATRIX(I, I)
  100 NEXT I
  110 PRINT "Trace = "; TOTAL
  120 PRINT "Log10 = "; LOG10(TOTAL)

GOAL: A dialect optimized for text adventure games and

  Name: "StoryBasic"
  Code: "STRY"

  Features:
  - SAY replaces PRINT (via ALIAS)
  - ASK replaces INPUT
  - PAUSE command for dramatic timing
  - CLS for scene transitions
  - All string functions available
  - Simplified error messages

  Config:
  {
      DIALECT_STORY,
      "StoryBasic",
      ':',  1, 1, 1, 1, 0, 0, 1, 0, 0, 9999, 0,
      1, 1, 0, 1, 0,
      0, 1, 1,
      ">>> ",  40, 0, 1, 0, "STRY",
      (1u << 14)
  },

  Companion module adds game-specific functions:

  BValue fn_roll(BValue *args, int argc, void *rt)
  {
      /* ROLL(6) = random 1-6 (dice roll) */
      int sides = (int)bval_to_int(&args[0]);
      (void)argc; (void)rt;
      if (sides < 1) sides = 6;
      return bval_int((rand() % sides) + 1);
  }

  BValue fn_pause(BValue *args, int argc, void *rt)
  {
      /* PAUSE 2 = wait 2 seconds */
      int ms = (int)(bval_to_float(&args[0]) * 1000.0);
      (void)argc; (void)rt;
      vdev_sleep(ms);
      return bval_int(0);
  }

  Usage:
    DIALECT "STRY"
    10 CLS
    20 PRINT "You stand at the entrance to a dark cave."
    30 PRINT "A cold wind blows from within."
    40 PRINT
    50 INPUT "Do you enter? (Y/N) "; A$
    60 IF UCASE$(A$) = "Y" THEN GOTO 100
    70 PRINT "You walk away safely."
    80 END
    100 PRINT "You step inside..."
    110 D = ROLL(20)
    120 IF D >= 10 THEN PRINT "You find treasure!" : END
    130 PRINT "A dragon appears!"
    140 END

11. TUTORIAL 4: RETRO MACHINE EMULATION (ZX SPECTRUM)
=====================================================================

GOAL: Emulate Sinclair ZX Spectrum BASIC as closely as
possible within BASIC++.

  Name: "ZX Spectrum BASIC"
  Code: "ZXSP"

  Historical characteristics:
  - Line numbers required (1-9999)
  - PRINT can be shortened to ? (already supported)
  - LET is required
  - NEXT without variable: NEXT (not NEXT I)
  - GO TO / GO SUB (two words) — alias to GOTO/GOSUB
  - BORDER, INK, PAPER for colors (stubbed)
  - PEEK/POKE for memory access
  - BEEP pitch, duration (different syntax)
  - RANDOMIZE replaces RANDOMIZE N
  - VAL$() function (evaluates string as expression)

  Config:
  {
      DIALECT_SPECTRUM,
      "ZX Spectrum BASIC",
      ':',  1, 0, 1, 1, 0, 0, 1, 1, 0, 9999, 0,
      1, 0, 0, 0, 0,
      1, 1, 1,
      "0 OK, 0:1",  32, 0, 1, 0, "ZXSP",
      (1u << 15)
  },

  Notes:
  - has_let_optional = 0 (LET is required on Spectrum)
  - has_while_wend = 0 (no WHILE on original Spectrum)
  - has_extended_vars = 0 (short variable names)
  - ready_prompt = "0 OK, 0:1" (Spectrum's actual OK message)
  - max_line_number = 9999

14. OVERRIDING FUNCTION BEHAVIOR (funcreg_override)
=====================================================================

Different BASIC dialects implement the same functions
differently.  The function registry's override mechanism
lets you swap handler implementations per dialect.

EXAMPLE: RND() behavior varies:

  GW-BASIC / QBasic:
    RND       Returns random float 0-1
    RND(0)    Repeats last random number
    RND(n>0)  Returns new random float 0-1
    RND(n<0)  Seeds and returns new random

  Commodore BASIC:
    RND(0)    Uses hardware timer for seed
    RND(n>0)  Returns random float 0-1
    RND(n<0)  Seeds with n

  PATB:
    RND(n)    Returns random integer 1 to n

  To override RND for Commodore behavior:

    static BValue c64_rnd(BValue *args, int argc, void *rt)
    {
        double x = bval_to_float(&args[0]);
        (void)argc; (void)rt;
        if (x == 0.0) {
            /* Use time-based seed */
            srand((unsigned)time(NULL));
        } else if (x < 0.0) {
            srand((unsigned)(x * 1000.0));
        }
        return bval_float((double)rand() / (double)RAND_MAX);
    }

    /* In dialect_apply() for Commodore: */
    funcreg_override(KW_RND, c64_rnd);

  Rules for overriding:
    - Only functions marked overridable=1 can be overridden
    - The replacement must match the original signature
    - Override persists until another dialect_apply()
    - funcreg_override() returns -1 for non-overridable functions

15. CREATING A DIALECT MODULE (mod_dialect.c)
=====================================================================

Package your dialect as a proper module:

  /* mod_spectrum.c - ZX Spectrum BASIC dialect */
  #include "module.h"
  #include "dialect.h"
  #include "funcreg.h"

  /* Custom functions for Spectrum BASIC */
  static BValue fn_ink(BValue *a, int c, void *r)
  { (void)c;(void)r;
    /* Set foreground color (stubbed) */
    printf("\033[3%ldm", bval_to_int(&a[0]) % 8);
    return bval_int(0); }

  static BValue fn_paper(BValue *a, int c, void *r)
  { (void)c;(void)r;
    /* Set background color (stubbed) */
    printf("\033[4%ldm", bval_to_int(&a[0]) % 8);
    return bval_int(0); }

  static BValue fn_border(BValue *a, int c, void *r)
  { (void)c;(void)r;
    /* Set border color (no-op on modern terminals) */
    return bval_int(0); }

  static const FunctionEntry spectrum_funcs[] = {
      {"INK",    KW_COUNT, FCAT_IO, FRET_INT, 1,1,
       FSAFE_IO, 0, fn_ink, "Set ink color"},
      {"PAPER",  KW_COUNT, FCAT_IO, FRET_INT, 1,1,
       FSAFE_IO, 0, fn_paper, "Set paper color"},
      {"BORDER", KW_COUNT, FCAT_IO, FRET_INT, 1,1,
       FSAFE_IO, 0, fn_border, "Set border color"},
  };

  static int spectrum_init(void *rt)
  {
      int i;
      (void)rt;
      /* Switch to Spectrum dialect */
      dialect_init(DIALECT_SPECTRUM);
      dialect_apply();
      /* Register Spectrum-specific functions */
      for (i = 0; i < 3; i++)
          funcreg_register(&spectrum_funcs[i]);
      return 0;
  }

  static const ModuleInfo spectrum_module = {
      "SPECTRUM", "1.0",
      "ZX Spectrum BASIC emulation",
      MOD_DIALECT, CAP_IO,
      spectrum_init, NULL
  };

  void mod_spectrum_register(void)
  { module_register(&spectrum_module); }

  Usage from BASIC:
    MODULE "SPECTRUM"
    10 BORDER 1
    20 PAPER 0
    30 INK 7
    40 CLS
    50 PRINT "SINCLAIR ZX SPECTRUM"

17-20. ADDITIONAL CONFIG OPTIONS

17. PRINT Zone Widths:
  Zone width controls comma-separated PRINT output:
    PRINT A, B, C
  Zone 8:   "12345678" per column  (PATB)
  Zone 10:  "1234567890" per column (Atari, C64)
  Zone 14:  "12345678901234" per column (GW-BASIC, QBasic)
  Zone 16:  "1234567890123456" per column (Apple, CoCo)

18. Statement Separators:
  PATB uses ';' (semicolon): PRINT A; INPUT B
  All others use ':' (colon): PRINT A : INPUT B
  Set via stmt_separator in DialectConfig.

19. Variable Naming:
  has_extended_vars = 0: Variables are A-Z (26 vars)
  has_extended_vars = 1: Variables can be TOTAL, COUNT$, etc.
  Single-letter mode forces A-Z for numerics, A$-Z$ for strings.

20. Line Number Ranges:
  Different machines used different ranges:
    PATB:       1-32767 (15-bit signed integer)
    GW-BASIC:   0-65529
    ECMA-55:    1-99999 (5 digits)
    Spectrum:   1-9999

=====================================================================
21. DESIGN PHILOSOPHY
=====================================================================

BASIC++ can serve as the foundation for a completely custom
scripting language.  You're not limited to BASIC syntax —
through dialects, aliases, modules, and lexer extensions,
you can create something entirely new.

The key insight: BASIC++'s engine is a general-purpose
interpreter.  The "BASIC" part is just the default dialect.
You can replace every visible keyword, every prompt, and
every behavior — while keeping the proven engine underneath.

APPROACH 1: Dialect + Aliases (no recompilation)
  Use ALIAS to rename keywords.  Quick, easy, no C code.
  Limited to renaming existing keywords.

APPROACH 2: Dialect + Module (compiled in)
  Create a C module that registers new functions.
  More powerful, requires recompilation.

APPROACH 3: Full Lexer Extension (advanced)
  Add new keywords to the lexer and new handlers to the VM.
  Maximum power, requires deep source modification.


=====================================================================
22. TUTORIAL: "MicroScript" — A NON-BASIC LANGUAGE
=====================================================================

Let's create a simple scripting language called "MicroScript"
that looks nothing like BASIC:

  MicroScript syntax:
    display "Hello World"         (= PRINT)
    ask "Name? " into name$       (= INPUT)
    set x = 42                    (= LET)
    when x > 10 do                (= IF...THEN)
    repeat 5 times                (= FOR I = 1 TO 5)
    until done                    (= WEND / NEXT)

Step 1: Create a dialect config with all BASIC features
        enabled but custom personality:

  {
      DIALECT_MICROSCRIPT,
      "MicroScript",
      ':',  1, 1, 1, 1, 0, 0, 1, 1, 0, 9999, 0,
      1, 1, 0, 1, 0,
      1, 1, 1,
      ">> ",  14, 0, 1, 0, "USCR",
      (1u << 12)
  },

Step 2: Use ALIAS to map MicroScript keywords:

  ALIAS "DISPLAY" "PRINT"
  ALIAS "ASK" "INPUT"
  ALIAS "SET" "LET"
  ALIAS "WHEN" "IF"
  ALIAS "DO" "THEN"
  ALIAS "REPEAT" "FOR"
  ALIAS "TIMES" "NEXT"

Step 3: Write programs in MicroScript syntax:

  10 DISPLAY "Welcome to MicroScript!"
  20 ASK "What is your name? "; N$
  30 DISPLAY "Hello, "; N$
  40 SET X = 0
  50 REPEAT I = 1 TO 5
  60   SET X = X + I
  70 TIMES I
  80 DISPLAY "Sum: "; X
  90 END

The interpreter still runs BASIC++ underneath, but the
user sees MicroScript syntax.


=====================================================================
23. KEYWORD MAPPING VIA ALIAS
=====================================================================

The ALIAS system (when implemented) allows renaming any
keyword without modifying the lexer:

  ALIAS "source_keyword" "target_keyword"

  The lexer first checks the alias table.  If a match is
  found, the aliased keyword is used instead.

  Example: Create a French BASIC:
    ALIAS "AFFICHER" "PRINT"
    ALIAS "SAISIR" "INPUT"
    ALIAS "SI" "IF"
    ALIAS "ALORS" "THEN"
    ALIAS "SINON" "ELSE"
    ALIAS "POUR" "FOR"
    ALIAS "A" "TO"
    ALIAS "SUIVANT" "NEXT"
    ALIAS "TANTQUE" "WHILE"
    ALIAS "FIN" "END"

  Now you can write:
    10 AFFICHER "Bonjour!"
    20 SAISIR "Votre nom? "; N$
    30 SI LEN(N$) > 0 ALORS AFFICHER "Bienvenue, "; N$
    40 FIN

  Example: Create a Python-ish dialect:
    ALIAS "DEFINE" "DEF FN"
    ALIAS "WHILE" "WHILE"
    ALIAS "ENDWHILE" "WEND"

  Example: Create a Lua-ish dialect:
    ALIAS "LOCAL" "DIM"
    ALIAS "FUNCTION" "DEF FN"
    ALIAS "IO.WRITE" "PRINT"


=====================================================================
24. ADDING NEW KEYWORDS TO THE LEXER
=====================================================================

For deeper customization, add new keywords directly to the
lexer.  This requires modifying the C source.

Step 1: Add to KeywordId enum in lexer.h:

  KW_DISPLAY,       /* DISPLAY = PRINT alias */
  KW_SPAWN,         /* SPAWN = new keyword */
  KW_AWAIT,         /* AWAIT = new keyword */

Step 2: Add to the keyword table in lexer.c:

  {"DISPLAY",  KW_DISPLAY,  DFLAG_ALL},
  {"SPAWN",    KW_SPAWN,    (1u << 12)},  /* your dialect only */
  {"AWAIT",    KW_AWAIT,    (1u << 12)},

Step 3: The lexer will now recognize these keywords.

Step 4: Add handlers to the VM (see section 25).


=====================================================================
25. ADDING NEW STATEMENTS TO THE VM
=====================================================================

Once a keyword exists in the lexer, add a handler:

Step 1: Write the handler function:

  static void parse_spawn(Lexer *lex, void *rt, int line_num)
  {
      /* SPAWN subroutine_line */
      BValue val = expr_evaluate(lex, rt, line_num);
      int target = (int)bval_to_int(&val);
      (void)line_num;
      /* ... implementation ... */
  }

Step 2: Register in the VM dispatch table:

  vm_register_handler(KW_SPAWN, parse_spawn);

Step 3: The statement is now callable:

  SPAWN 1000        ' Call subroutine asynchronously

26. BUILDING A COMPLETE LANGUAGE MODULE
=====================================================================

Package everything as a self-contained module:

  mod_microscript.c:
  - Dialect config (personality, feature flags)
  - Custom functions (ROLL, PAUSE, CHOOSE, etc.)
  - Function overrides (custom PRINT behavior)
  - Module descriptor with init/cleanup

  mod_microscript.h:
  - void mod_microscript_register(void);

  main.c integration:
  - #include "mod_microscript.h"
  - mod_microscript_register();

  From BASIC:
  - MODULE "MICROSCRIPT" activates everything

The module pattern keeps your language extension self-contained.
Add mod_microscript.c to the build, and your language is
available via a single MODULE command.

=====================================================================
27. ADDING STRUCTURED PROGRAMMING
=====================================================================

BASIC++ already supports several structured constructs.
Here's how to add more:

BLOCK IF / ELSEIF / END IF:

  IF condition THEN
      statements
  ELSEIF condition THEN
      statements
  ELSE
      statements
  END IF

  Implementation approach:
  1. When IF is followed by THEN and a newline (no statement
     after THEN), enter "block IF" mode
  2. Track nesting depth via a counter
  3. ELSEIF tests the next condition
  4. ELSE handles the default case
  5. END IF closes the block

SELECT CASE:

  SELECT CASE expression
      CASE value1
          statements
      CASE value2, value3
          statements
      CASE IS > 100
          statements
      CASE ELSE
          statements
  END SELECT

  Implementation:
  1. Evaluate the SELECT expression once
  2. Compare against each CASE value
  3. Execute the matching block
  4. Skip to END SELECT


=====================================================================
28. ADDING OBJECT-LIKE CONSTRUCTS
=====================================================================

While BASIC++ is not object-oriented, you can add
TYPE structures for grouping related data:

  TYPE PersonType
      Name AS STRING * 30
      Age AS INTEGER
      Salary AS DOUBLE
  END TYPE

  DIM Employee AS PersonType
  Employee.Name = "Alice"
  Employee.Age = 30
  Employee.Salary = 75000

  Implementation approach:
  1. TYPE defines a record template (like C struct)
  2. Store field definitions in a type registry
  3. DIM ... AS TypeName allocates the fields
  4. Dot notation (Employee.Name) resolves to a
     field offset within the record


=====================================================================
29. ADDING EVENT-DRIVEN PROGRAMMING
=====================================================================

Classic BASIC has limited event handling.  Add more:

  ON TIMER(seconds) GOSUB line
  ON KEY(n) GOSUB line
  ON SIGNAL(n) GOSUB line
  ON ERROR GOTO line          (already implemented)

  Implementation:
  1. Register event handlers in an event table
  2. After each statement executes, check the event queue
  3. If an event is pending, push the return address and
     GOSUB to the handler
  4. RETURN resumes from where the event occurred


=====================================================================
30. ADDING CONCURRENCY PRIMITIVES
=====================================================================

For advanced applications, add cooperative multitasking:

  SPAWN line_number      ' Start a coroutine
  YIELD                  ' Yield to next coroutine
  WAIT condition         ' Block until condition is true
  CHANNEL n              ' Switch to a communication channel

  Implementation approach:
  1. Each "task" has its own program counter and stack
  2. YIELD saves the current task state and switches
     to the next task in a round-robin schedule
  3. WAIT blocks the current task (removes from schedule)
  4. The main loop rotates through active tasks

Write a test that exercises every feature:

  1 REM === Dialect Test Suite ===

  130 PRINT "WHILE: "; J

  190 GOSUB 500
