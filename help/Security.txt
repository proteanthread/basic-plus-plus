BASIC++ v6.5.2 SECURITY ARCHITECTURE & SECURE CODING PRACTICES

The authoritative specification of the BASIC++ six-level virtual execution
sandbox, access control enforcement mechanisms, command-line security flags,
and defensive secure coding patterns for application developers.


1. ARCHITECTURAL OVERVIEW & VIRTUAL DEVICE ENFORCEMENT

BASIC++ implements a unified six-level security sandbox
(engine/src/security/security.c in libkernel). Rather than scattering
ad-hoc security checks across hundreds of individual keyword handlers,
security enforcement is anchored at the virtual hardware layer:
- Virtual Filesystem (VFS): Intercepts path resolution, restricting
  directory traversal and file write operations (engine/src/runtime/vfs.c).
- Virtual Network (VNet): Blocks socket allocation and network listening
  (engine/src/runtime/vnet.c).
- Virtual Device Bus (VDev): Controls peripheral bindings, hardware port
  access, and system calls (engine/src/device/vdev.c).


2. THE SIX SECURITY LEVELS

Level  Identifier       Name         Capabilities & Sandbox Boundary
-----  ---------------  -----------  ---------------------------------------
  0    SEC_OPEN         OPEN         Unrestricted host access. All allowed.
  1    SEC_SAFE         SAFE         Safe dev. File deletion limited to CWD.
  2    SEC_STANDARD     STANDARD     Sandboxed. Writes in CWD only. No SHELL.
  3    SEC_EDUCATIONAL  EDUCATIONAL  Classroom. Read/write CWD. No create.
  4    SEC_RESTRICTED   RESTRICTED   Isolated. No file I/O, net, POKE/OUT.
  5    SEC_PARANOID     PARANOID     Pure computation. All I/O forbidden.

Host Command-Line Execution Flags:

    baspp --security=2              # Standard sandbox for desktop
    bpp --security=4                # Restricted mode for terminal REPL
    bs --security=3 student.bas     # Classroom sandbox for script

Elevating Security from BASIC:

    10 SECURITY 3                   ' Elevate sandbox to Educational level

The SECURITY statement can only raise the security level, never lower it.
Once elevated, it cannot be reduced without restarting the process.

4. DEFENSIVE SECURE CODING PRACTICES

Strict Input Validation & Length Bounds:

    10 LINE INPUT "Enter Username (max 20 characters): "; U$
    20 IF LEN(U$) = 0 OR LEN(U$) > 20 THEN
    30   PRINT "Error: Username must be between 1 and 20 characters."
    40   GOTO 10
    50 END IF

Path Traversal Defense:

    100 FUNCTION SanitizeFilename$(raw$)
    110   clean$ = ""
    120   FOR I = 1 TO LEN(raw$)
    130     C$ = MID$(raw$, I, 1)
    140     IF C$ <> "/" AND C$ <> "\" AND C$ <> ":" THEN
    150       clean$ = clean$ + C$
    160     END IF
    170   NEXT I
    180   SanitizeFilename$ = clean$
    190 END FUNCTION

Preventing Command Injection:

    10 INPUT "Select Option [1-3]: "; Opt%
    20 IF Opt% < 1 OR Opt% > 3 THEN PRINT "Invalid choice." : END
    30 ' Pass strictly validated ordinal integers rather than raw input
