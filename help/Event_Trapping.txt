==============================================================================
BASIC++ v6.5.2 Event Trapping
==============================================================================

1. THE EVENT SYSTEM

BASIC++ implements an asynchronous event monitoring architecture that tracks
hardware and software events during program execution. When an enabled event
condition is detected, the virtual machine interrupts standard sequential
execution and transfers control to a user-defined subroutine. Upon reaching
RETURN, normal program execution resumes precisely where it was interrupted.

The event subsystem is implemented in engine/src/vm/events.c. Event polling
occurs deterministically at statement boundaries: the VM checks the pending
event queue after each statement completes. This guarantees thread safety and
prevents reentrancy corruption of the runtime evaluation stack.

2. EVENT TRAPPING SYNTAX PATTERN

All event trapping statements conform to a standardized three-part lifecycle:
1. Declare the Handler: ON event GOSUB line defines the subroutine that
   processes the event.
2. Enable Monitoring: event ON activates polling and trap firing.
3. Execute and Return: The handler subroutine processes the event and
   executes RETURN to resume the interrupted code.

Events can be controlled dynamically:
* event ON: Enables event polling and immediate handler invocation.
* event OFF: Disables event monitoring; occurrences during this state are
  ignored.
* event STOP: Suspends handler execution while queuing incoming occurrences.
  When event ON is subsequently executed, any queued event fires immediately.

3. KEY TRAPPING

ON KEY(n) GOSUB line traps specific keyboard events:
* Keys 1-10: Function keys F1 through F10.
* Keys 11-14: Cursor movement keys (Up, Down, Left, Right).
* Keys 15-25: User-defined key combinations configured via
  KEY n, CHR$(shift) + CHR$(scancode).

Example:

    10 ON KEY(1) GOSUB 1000    ' Trap F1 press
    20 KEY(1) ON               ' Enable trap
    30 PRINT "Press F1 for help, or any other key to continue..."
    40 A$ = INPUT$(1)
    50 KEY(1) OFF
    60 END
    1000 PRINT "Help: BASIC++ Event Trapping Demonstration"
    1010 RETURN

4. TIMER TRAPPING

ON TIMER(n) GOSUB line triggers an event every n seconds:

    10 ON TIMER(2) GOSUB 1000   ' Fire handler every 2 seconds
    20 TIMER ON
    30 FOR I = 1 TO 10
    40   PRINT "Working..."; I
    50   SLEEP 1
    60 NEXT I
    70 TIMER OFF
    80 END
    1000 PRINT "[TIMER EVENT: "; TIME$; "]"
    1010 RETURN

The timer argument n represents elapsed seconds (1 to 86400). Fractional
timer values are rounded to the nearest second.

5. COM PORT TRAPPING

ON COM(n) GOSUB line monitors serial communications port n (1 through 8):

    10 OPEN "COM1:9600,N,8,1" AS #1
    20 ON COM(1) GOSUB 1000
    30 COM(1) ON
    40 WHILE INKEY$ <> CHR$(27) : WEND
    50 COM(1) OFF
    60 CLOSE #1
    70 END
    1000 INPUT #1, Packet$
    1010 PRINT "Received: "; Packet$
    1020 RETURN

The trap fires whenever incoming characters arrive in the serial channel
receive buffer.

6. PLAY TRAPPING

ON PLAY(n) GOSUB line triggers when the background music buffer falls below n
notes (1 to 32). This allows continuous background music playback by queuing
new note sequences into PLAY without blocking foreground execution:

    10 ON PLAY(4) GOSUB 1000
    20 PLAY ON
    30 PLAY "MB T120 O3 C D E F G A B"
    40 WHILE Playing% : WEND
    50 PLAY OFF
    60 END
    1000 PLAY "MB O4 C D E F"
    1010 RETURN

7. EVENT QUEUING AND PRIORITY RULES

1. While an event handler is executing, the triggering event is temporarily
   placed in STOP mode automatically, preventing recursive handler reentrancy.
2. If multiple event types trigger simultaneously, they are serviced
   according to fixed subsystem priorities: Error traps take highest priority,
   followed by Timer events, Keyboard events, Serial COM events, and Audio
   Play events.
3. Trapped subroutines must exit using standard RETURN. Using GOTO out of an
   event handler leaves the event state suspended and leaks an event
   activation frame on the execution stack.
