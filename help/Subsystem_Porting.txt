BASIC++ SUBSYSTEM PORTING AND MICRO-LIBRARY EXTRACTION

The engineering guide detailing how to isolate, extract, and reuse
individual BASIC++ subsystems and micro-libraries in standalone external
applications.


1. MODULAR SUBSYSTEM ARCHITECTURE

BASIC++ v6.5.2 organizes all engine subsystems into an 11-modular library
spectrum linked accumulatively (libboot through libadvanced, plus
libinterop_core). Subsystems are designed with explicit unidirectional
dependencies, allowing clean extraction of specific subsystems without linking
the entire desktop runtime.

1.1 Accumulative Library Chain
- libboot     : Bootstrap sequence controller (freestanding C17, no deps).
- libplatform : Operating system abstraction layer (plat_console, plat_fs).
- libkernel   : VM context, lexer, memory, security sandbox, BIOS, VDev bus.
- libengine   : AST evaluator, RPN engine, parser, runtime variables.
- libhardware : Segmented memory (vmem), BGI software rasterizer, FujiNet.
- libserver   : Network sockets (vnet), Gemini protocol, background tasks.
- libscript   : Headless batch runner, file system statement handlers.
- libcore     : Foundational REPL, numeric formatter, metadata registry.
- libflex     : Dynamic metaprogramming (ALIAS, OVERRIDE, SCOPE), modules.
- libstandard : Multi-window TUI editor multiplexer, DAP debug server.
- libadvanced : Desktop visual graphics, multimedia, SDL2/OpenGL bindings.


2. EXTRACTING STANDALONE SUBSYSTEMS

2.1 Extracting the BIOS Subsystem (libbios)
The PC/XT/AT BIOS emulator (engine/src/bios/) provides complete virtual BIOS
interrupt emulation:
1. Copy engine/src/bios/ and engine/include/bios/.
2. Compile under freestanding ISO C17 with standard integer types.
3. Bind the BiosHAL dispatch struct to your host environment.
4. Provides full PC interrupt trapping (INT 10h, 13h, 16h, 1Ah) with zero
   external engine dependencies.

2.2 Extracting the BGI Rasterizer Subsystem (libbgi)
The Borland Graphics Interface rasterizer (engine/src/device/bgi/) provides
software graphics rendering:
1. Copy engine/src/device/bgi/ and engine/include/device/bgi/.
2. Supply a linear framebuffer pointer (uint8_t* framebuffer).
3. Provides line drawing, circle/arc rasterization, flood fill, polygon
   clipping, and vector stroke font rendering.

2.3 Extracting the Lexer and Tokenizer
The lexical scanner (engine/src/lexer/lexer.c) can be extracted into external
tools and IDE formatters:
1. Copy engine/src/lexer/ and engine/include/lexer/.
2. Copy engine/include/types/ for token enumerations.
3. Performs zero-copy lexical tokenization across all vintage and modern
   BASIC keywords.
