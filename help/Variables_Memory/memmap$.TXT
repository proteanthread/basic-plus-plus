MEMMAP$

1. Syntax & Parameters

MEMMAP$

Parameters:
- None. MEMMAP$ is a parameterless system variable (function) that requires no arguments and no parentheses.

2. Description & Usage

The MEMMAP$ function returns a string indicating the currently active virtual BIOS/memory map configuration of the BASIC++ environment. Because BASIC++ provides an extensive virtual machine layer that can mock various historic 8-bit and 16-bit architectures, MEMMAP$ is vital for runtime introspection.

By default, BASIC++ boots into an IBM PC compatible virtual memory mode, so MEMMAP$ will typically return "IBMPC" or "MSDOS" unless the user has explicitly changed the memory map via command-line arguments (e.g., --mmap C64) or runtime directives. 

This is particularly useful when writing portable BASIC scripts that might need to query hardware-specific capabilities, such as whether it's safe to PEEK and POKE certain legacy video memory segments (like &HB800 for PC CGA text memory or 53280 for C64 border color).

The value returned is read-only. It cannot be directly modified through assignment (e.g., MEMMAP$ = "C64" is illegal).

Returns one of the predefined strings from the internal map list (e.g., "NONE", "MSDOS", "IBMPC", "PCJR", "PCXT", "PCAT", "C64", "C128", "VIC20", "PLUS4", "PET", "ATARI8", "APPLE2", "TRS80", "SPECTRUM", "QL").

3. Code Examples

Example 1: Basic Usage
`basic
10 PRINT "Current Memory Map: "; MEMMAP$
`

Example 2: Conditional Hardware Pokes
`basic
10 MAP$ = MEMMAP$
20 IF MAP$ = "C64" THEN GOTO 100
30 IF MAP$ = "IBMPC" OR MAP$ = "MSDOS" THEN GOTO 200
40 PRINT "Unknown hardware profile: "; MAP$
50 END
100 REM Commodore 64 specific initialization
110 POKE 53280, 0 : POKE 53281, 0 : REM Set background and border to black
120 GOTO 300
200 REM IBM PC specific initialization
210 DEF SEG = &HB800 : REM Set segment to CGA video memory
220 GOTO 300
300 PRINT "System initialized."
`

Example 3: Checking length for formatting
`basic
10 M$ = MEMMAP$
20 PRINT "System: ["; M$; "]"
30 PRINT "Length: "; LEN(M$); " characters"
`

5. Implementation Details

- Parser Expectations: The AST builder explicitly treats MEMMAP$ as a parameterless system built-in (AstFuncId / PCODE_FUNC1). Because it has no parameters, the execution stack must cleanly pop the empty argument context to prevent stack underflow. This was explicitly hardened during a recent architectural update.
- Mutability Constraints: MEMMAP$ is strictly an intrinsic system function, not a mutable variable. It evaluates dynamically at runtime by fetching the string corresponding to rt->memmap_type. Any attempt to parse it as an L-value (e.g., MEMMAP$ = "X") will trigger a syntax error.
- Troubleshooting: If MEMMAP$ returns "UNKNOWN", it implies that the internal rt->memmaptype enum has lost synchronization with the memmaptable[] in memmap.c. If you encounter stack underflows when evaluating MEMMAP$ inside complex expressions, check vmexec.c to ensure that fid >= FUNCMEMMAP is properly routed to the correct parameterless function evaluation path.

7. Historical Context

- GW-BASIC / QBASIC: MEMMAP$ did not exist in GW-BASIC or QBASIC. Those interpreters were strictly bound to the IBM PC real-mode environment and had no concept of cross-architecture virtual hardware mocking.
- ECMA-116 Standard: Not defined in standard minimal or full BASIC. 
- BASIC++: Introduced explicitly to support BASIC++'s multi-architecture virtual memory layer (e.g., MMAPC64, MMAPAPPLE2), allowing single scripts to conditionally adjust their PEEK/POKE offsets based on the currently mocked BIOS.

8. Manual Testing Guide

To manually test MEMMAP$ in the console without automated Python suites:

1. Launch the standard console interpreter for your OS:
   - Windows: basicpp-console.exe
   - Linux: ./baspp-console
2. At the Ready. prompt, enter the following direct command:
   PRINT MEMMAP$
3. Press Enter. The interpreter should output the default map name, typically IBMPC or MSDOS.
4. Exit the interpreter by typing SYSTEM.
5. Launch the interpreter again, but explicitly specify a different memory map profile via the command line (if your build supports the --mmap switch, e.g., basicpp-console.exe --mmap C64). 
6. Type PRINT MEMMAP$ again to verify that the output reflects the new profile (e.g., C64).
