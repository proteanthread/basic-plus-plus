MIXING DIALECTS IN BASIC++
==========================
Version 4.0.1

BASIC++ is the union of all BASIC dialects.  This means you
can mix features from GW-BASIC, QBasic, Commodore, Apple,
Spectrum, Atari, and more — in the SAME program.

This manual explains how dialect mixing works, why you'd want
to do it, what the rules are, how to avoid problems, and how
to use dialect mixing as a foundation for creating advanced
programs that draw on the best features of every BASIC family.

1. THE UNION PRINCIPLE
=====================================================================

BASIC++ follows one core philosophy:

  "BASIC++ is the UNION of all BASIC dialects."

This means:
  - Every keyword from every supported dialect works
  - Every feature from every dialect is available
  - You never need to choose ONE dialect
  - You can freely combine features from different BASICs
  - No feature from any classic BASIC is excluded

In practice:
  - GW-BASIC's WHILE/WEND works alongside QBasic's DO/LOOP
  - Commodore's PEEK/POKE works alongside ECMA-116's matrices
  - Dartmouth's MAT operations work alongside GW-BASIC's SCREEN
  - Tiny BASIC's @() arrays work alongside DIM arrays

The BPP (BASIC++) dialect is the default.  It accepts
ALL keywords from ALL dialects.  You only switch to a
specific dialect when you want STRICT mode enforcement.

=====================================================================
4. SWITCHING DIALECTS AT RUNTIME
=====================================================================

The DIALECT command changes the active dialect:

  DIALECT "GWBS"      ' Switch to GW-BASIC mode
  DIALECT "QBAS"      ' Switch to QBasic mode
  DIALECT "BPP"       ' Switch back to BASIC++ (union)
  DIALECT              ' List all available dialects

The switch is IMMEDIATE.  From that point forward:
  - The ready prompt changes
  - The PRINT zone width changes
  - Feature flags are updated
  - In strict mode, keyword filtering changes

In a program:
  10 DIALECT "GWBS"
  20 PRINT "Now in GW-BASIC mode"
  30 REM The prompt says "Ok" if you break here
  40 DIALECT "C64B"
  50 PRINT "Now in Commodore mode"
  60 REM The prompt says "READY." if you break here
  70 DIALECT "BPP"
  80 PRINT "Back to BASIC++"

IMPORTANT: Existing program lines in memory are NOT
re-parsed.  They are checked against the new dialect's
rules when they EXECUTE, not when the dialect switches.


=====================================================================
5. UNION MODE VS STRICT MODE
=====================================================================

UNION MODE (default):
  All keywords from all dialects are accepted.
  This is the normal operating mode for BASIC++.

    DIALECT "PATB"          ' Set PATB as active
    10 WHILE 1              ' WHILE works! (not in original PATB)
    20   PRINT "Hello"
    30 WEND
    ' No error — union mode accepts everything

STRICT MODE:
  Only keywords belonging to the active dialect are accepted.
  Enable with OPTION STRICT.

    DIALECT "PATB"
    OPTION STRICT
    10 WHILE 1              ' ERROR! WHILE not in PATB
    ' WHAT? Unknown keyword in strict PATB mode

  Strict mode is useful for:
  - Verifying portability to a specific dialect
  - Teaching: ensuring students use only allowed constructs
  - Emulation: accurate behavior testing
  - Debugging: finding dialect-specific issues

  Disable strict mode:
    OPTION STRICT OFF

=====================================================================
6. MIXING FEATURES IN BPP MODE (SIMPLEST)
=====================================================================

In BPP mode (the default), you can freely use features
from any dialect.  No DIALECT command needed:

  10 REM This program mixes features from 5 dialects
  20 REM
  30 REM Tiny BASIC's @() array syntax:
  40 LET @(0) = 42
  50 REM
  60 REM GW-BASIC's WHILE/WEND:
  70 I = 0
  80 WHILE I < 5
  90   I = I + 1
  100 WEND
  110 REM
  120 REM QBasic's DO/LOOP:
  130 J = 0
  140 DO
  150   J = J + 1
  160 LOOP UNTIL J >= 5
  170 REM
  180 REM Dartmouth's DATA/READ:
  190 DATA 10, 20, 30
  200 READ A, B, C
  210 REM
  220 REM ECMA-116's structured control:
  230 IF A > 5 THEN
  240   PRINT "A is greater than 5"
  250 ELSE
  260   PRINT "A is 5 or less"
  270 END IF
  280 REM
  290 PRINT "All dialect features working!"
  300 END

This is the simplest and most common way to mix dialects.
Just use whatever features you need.


=====================================================================
7. SWITCHING DIALECTS MID-PROGRAM
=====================================================================

Sometimes you want to switch dialects to change BEHAVIOR
(not just keywords).  This affects:
  - The ready prompt (if the program stops)
  - PRINT zone widths (column alignment)
  - Future: function behavior (RND, etc.)

  10 DIALECT "GWBS"
  20 REM This section uses GW-BASIC PRINT formatting
  30 REM Zone width: 14 columns per comma tab
  40 PRINT "Name", "Age", "City"
  50 PRINT "Alice", 30, "NYC"
  60 PRINT "Bob", 25, "LA"
  70 PRINT
  80 DIALECT "C64B"
  90 REM Now Commodore formatting
  100 REM Zone width: 10 columns per comma tab
  110 PRINT "Name", "Age", "City"
  120 PRINT "Alice", 30, "NYC"
  130 PRINT "Bob", 25, "LA"
  140 DIALECT "BPP"
  150 END

  Output shows different column alignment because the
  zone width changed from 14 (GW-BASIC) to 10 (Commodore).


=====================================================================
8. USING GW-BASIC FEATURES IN QBASIC CODE
=====================================================================

GW-BASIC and QBasic are closely related (both Microsoft),
but each has unique features:

  GW-BASIC has but QBasic lacks:
    - KEY ON/OFF (function key display)
    - SCREEN modes 0-2 (CGA)
    - Some graphics modes

  QBasic has but GW-BASIC lacks:
    - SUB/FUNCTION block procedures
    - SELECT CASE
    - Long procedure names
    - Block IF/END IF (GW-BASIC has single-line IF)

  Mix them in BPP mode:

  10 REM Start with GW-BASIC-style line numbers
  20 SCREEN 0
  30 CLS
  40 REM Use QBasic-style structured IF:
  50 INPUT "Enter a number: "; N
  60 IF N > 0 THEN
  70   PRINT "Positive"
  80 ELSEIF N < 0 THEN
  90   PRINT "Negative"
  100 ELSE
  110   PRINT "Zero"
  120 END IF
  130 REM Use GW-BASIC's WHILE:
  140 WHILE INKEY$ = "" : WEND
  150 END

9. USING QBASIC FEATURES IN GW-BASIC CODE
=====================================================================

Port a GW-BASIC program and enhance it with QBasic features:

  10 REM === Original GW-BASIC program ===
  20 CLS
  30 PRINT "GW-BASIC Menu"
  40 PRINT "1. Add"
  50 PRINT "2. Subtract"
  60 PRINT "3. Quit"
  70 INPUT "Choice: "; C
  80 REM
  90 REM === Enhanced with QBasic SELECT CASE ===
  100 SELECT CASE C
  110   CASE 1
  120     INPUT "A, B: "; A, B
  130     PRINT "Sum = "; A + B
  140   CASE 2
  150     INPUT "A, B: "; A, B
  160     PRINT "Diff = "; A - B
  170   CASE 3
  180     PRINT "Goodbye"
  190     END
  200   CASE ELSE
  210     PRINT "Invalid choice"
  220 END SELECT
  230 GOTO 20


=====================================================================
10. MIXING MICROSOFT AND NON-MICROSOFT DIALECTS
=====================================================================

The Microsoft BASIC family (GW, QBasic, Commodore, Apple,
CoCo, TRS-80 II) shares a common core.  Non-Microsoft
dialects (PATB, ECMA-55, ECMA-116, Apple Integer) have
different conventions.

Key differences to watch:

  MICROSOFT FAMILY:
    - LET is optional: A = 5
    - Colon separates statements: PRINT A : PRINT B
    - <> is not-equal
    - Arrays start at 0 (default)
    - RND returns 0.0-1.0

  PALO ALTO TINY BASIC:
    - LET is optional: A = 5
    - SEMICOLON separates statements: PRINT A; PRINT B
    - # is not-equal
    - Arrays use @() syntax
    - RND(n) returns 1 to n (integer)

  ECMA-55:
    - LET is REQUIRED: LET A = 5
    - Colon separates statements
    - <> is not-equal
    - Arrays start at 0 (OPTION BASE changes this)

  Mixing safely:
  - Always use <> for not-equal (works in all except strict PATB)
  - Always use : for statement separator (works in all except PATB)
  - Use LET explicitly if portability matters
  - Use DIM for arrays (works in all dialects with arrays)


=====================================================================
11. MIXING RETRO DIALECTS (C64 + COCO + APPLE)
=====================================================================

Each retro machine had its own BASIC personality:

  C64:
    READY.                      (prompt)
    10 PRINT CHR$(147)          (clear screen - PETSCII)
    20 POKE 53280, 0            (border color - black)
    30 POKE 53281, 0            (background - black)
    40 PRINT "HELLO"

  CoCo:
    OK                          (prompt)
    10 CLS 0                    (clear screen - black)
    20 PRINT @256, "HELLO"      (print at screen position)

  Apple:
    ]                           (prompt)
    10 HOME                     (clear screen)
    20 HTAB 10 : VTAB 12       (position cursor)
    30 PRINT "HELLO"

  Mix them in BPP mode:
  10 REM Portable screen setup
  20 CLS
  30 PRINT "This works on all dialects"
  40 REM C64-style color (via POKE to MEMMAP)
  50 REM CoCo-style positioning (via PRINT @)
  60 REM Apple-style logic (via DATA/READ)
  70 DATA "Alice", 30, "Bob", 25, "Carol", 35
  80 FOR I = 1 TO 3
  90   READ N$, AGE
  100  PRINT N$; " is "; AGE; " years old"
  110 NEXT I
  120 END


=====================================================================
12. USING MODERN BASIC++ WITH RETRO SECTIONS
=====================================================================

A common pattern: write the main program in modern BASIC++
but include retro-compatible subroutines:

  1 REM === Main program (modern BASIC++) ===
  10 DIALECT "BPP"
  20 SECURITY "STANDARD"
  30 MODULE "MATHEXT"
  40 DIM Results(100)
  50 FOR Trial = 1 TO 100
  60   Results(Trial) = SIN(Trial * 0.1)  COS(Trial  0.05)
  70 NEXT Trial
  80 REM
  90 REM === Format output in GW-BASIC style ===
  100 DIALECT "GWBS"
  110 PRINT "Trial", "Result"
  120 PRINT "-----", "------"
  130 FOR I = 1 TO 10
  140   PRINT USING "###"; I;
  150   PRINT USING "    ##.######"; Results(I)
  160 NEXT I
  170 DIALECT "BPP"
  180 END

=====================================================================
13. WHAT CHANGES WHEN YOU SWITCH
=====================================================================

When you execute DIALECT "XXXX", the following change
IMMEDIATELY:

  Setting             Changes?  Effect
  -------             --------  ------
  Ready prompt        YES       Visual personality
  PRINT zone width    YES       Column alignment
  Feature flags       YES       What's allowed (in strict mode)
  Statement separator YES       How multi-stmt lines are parsed
  has_then_keyword    YES       IF parsing rules
  has_let_optional    YES       Assignment parsing rules
  max_line_number     YES       Line number range
  not_eq_is_hash      YES       Not-equal operator
  dialect_flag        YES       Keyword filtering (strict mode)

  What does NOT change:
  - Program lines already in memory
  - Variable values
  - Array contents
  - Open file channels
  - Active modules
  - Security level
  - MEMMAP contents

14. READY PROMPTS AND USER EXPERIENCE
=====================================================================

Each dialect has a historically accurate prompt:

  PATB:  READY
    The clean, confident prompt Li-Chen Wang chose.
    Appeared on teletype terminals in 1976.

  GW-BASIC / QBasic:  Ok
    Microsoft's friendly, casual prompt.
    Lowercase 'k' — informal and approachable.

  Commodore:  READY.
    With a period.  Formal, definitive.
    The C64's iconic blue screen with READY.

  AppleSoft:  ]
    Just a right bracket.  Minimal.
    The Apple ]['s characteristic prompt.

  Apple Integer:  >
    Greater-than sign.  Command-line feel.
    Wozniak's original BASIC.

  CoCo:  OK
    All caps.  The Color Computer's prompt.

  Atari:  READY
    Same as PATB — but with a different feel due to
    Atari's screen editor.

  ECMA-55 / E116:  READY
    Formal, standards-compliant.


=====================================================================
15. PRINT FORMATTING DIFFERENCES
=====================================================================

The PRINT statement behaves slightly differently across
dialects because of zone width:

  PRINT A, B, C

  Zone 8 (PATB):
    12345678123456781234567812345678
    A       B       C

  Zone 10 (Atari, C64):
    1234567890123456789012345678901234567890
    A         B         C

  Zone 14 (GW-BASIC, QBasic, ECMA, TRS-80 II):
    12345678901234123456789012341234567890
    A             B             C

  Zone 16 (Apple, CoCo, TRS-80 I):
    1234567890123456123456789012345612345678
    A               B               C

  This matters when formatting tables or reports.
  Switch to the dialect with the zone width you need.


=====================================================================
16-19. ADDITIONAL PERSONALITY DIFFERENCES
=====================================================================

16. VARIABLE NAMING:
  Named (has_extended_vars = 1):
    TOTAL = 100, CustomerName$ = "Alice"
  Single-letter (has_extended_vars = 0):
    T = 100, N$ = "Alice"

17. CONTROL FLOW:
  PATB: IF condition statement (no THEN required)
  All others: IF condition THEN statement
  GW/QBasic: IF...THEN...ELSE...END IF (block IF)
  QBasic only: SELECT CASE, SUB, FUNCTION

18. ERROR HANDLING:
  GW/QBasic/TRS2/ASFT/COCO: ON ERROR GOTO line
  Atari: TRAP line
  Others: no error trapping (errors halt the program)

19. FUNCTION AVAILABILITY:
  Integer-only (PATB, TRS1, AINT): No SIN, COS, TAN, etc.
  All Microsoft dialects: Full math + string functions
  ECMA-55: Math yes, limited string functions

20. THE COMPATIBILITY LAYER PATTERN
=====================================================================

Write a compatibility layer that normalizes dialect
differences:

  5000 REM === COMPATIBILITY LAYER ===
  5010 REM Call: GOSUB 5100 for portable CLS
  5020 REM Call: GOSUB 5200 for portable LOCATE
  5100 REM --- Portable Clear Screen ---
  5110 CLS
  5120 RETURN
  5200 REM --- Portable Cursor Position ---
  5210 REM Input: ROW, COL
  5220 PRINT CHR$(27); "["; ROW; ";"; COL; "H";
  5230 RETURN
  5300 REM --- Portable Delay ---
  5310 REM Input: MSEC (milliseconds)
  5320 T0 = TIMER
  5330 WHILE (TIMER - T0) * 1000 < MSEC : WEND
  5340 RETURN
  5400 REM --- Portable Key Wait ---
  5410 K$ = ""
  5420 WHILE K$ = "" : K$ = INKEY$ : WEND
  5430 RETURN

Now your main program uses GOSUB 5100 for clear screen
instead of CLS/HOME/CHR$(147)/etc.  The compatibility
layer handles the differences.


=====================================================================
21. THE FEATURE SCOPING PATTERN
=====================================================================

Use dialect switches to "scope" features to specific
sections of your program:

  10 DIALECT "BPP"
  20 REM Main logic in BASIC++ (full features)
  30 DIM DataArray(1000)
  40 OPEN "data.csv" FOR INPUT AS #1
  50 I = 0
  60 WHILE NOT EOF(1)
  70   I = I + 1
  80   INPUT #1, DataArray(I)
  90 WEND
  100 CLOSE #1
  110 REM
  120 REM Now format output in GW-BASIC style
  130 DIALECT "GWBS"
  140 PRINT "=== DATA REPORT ==="
  150 FOR J = 1 TO I
  160   PRINT USING "Record ###: #####.##"; J; DataArray(J)
  170 NEXT J
  180 DIALECT "BPP"
  190 END

The DIALECT switch at line 130 changes the PRINT zone
width for the report section, then switches back.

22. THE PROGRESSIVE ENHANCEMENT PATTERN

Start with a simple dialect and add features as needed:

  10 REM === Phase 1: Pure Tiny BASIC ===

  40 LET B = 1

  190 REM === Phase 3: Add BASIC++ extensions ===

  210 COMPILE "fibonacci.c"

=====================================================================
24. MIXING DIALECTS WITH MODULES
=====================================================================

Modules add new functions.  Dialects control which functions
are visible.  Combine them:

  10 MODULE "MATHEXT"           ' Adds CUBE, HYPOT, POW, etc.
  20 DIALECT "SCIB"             ' Scientific dialect personality
  30 OPTION STRICT              ' Only scientific keywords
  40 REM
  50 REM Now only scientific-approved keywords work
  60 PRINT "Hypotenuse: "; HYPOT(3, 4)
  70 PRINT "Cube root: "; POW(27, 1/3)
  80 PRINT "Log10(1000): "; LOG10(1000)

The module provides the functions.
The dialect provides the personality and restrictions.
Together they create a focused, domain-specific environment.


=====================================================================
25. MIXING DIALECTS WITH ALIAS
=====================================================================

ALIAS remaps keywords.  Combined with dialects, you can
create completely custom language experiences:

  DIALECT "BPP"
  ALIAS "SHOW" "PRINT"
  ALIAS "GET" "INPUT"
  ALIAS "LOOP" "FOR"
  ALIAS "ENDLOOP" "NEXT"
  ALIAS "STOP" "END"

  10 SHOW "Welcome to Custom BASIC!"
  20 GET "Enter your name: "; N$
  30 LOOP I = 1 TO 3
  40   SHOW I; ". Hello, "; N$
  50 ENDLOOP I
  60 STOP

The program looks like a custom language but runs on
the full BASIC++ engine.

For more on ALIAS, see G_Using_Aliases.txt.
For creating full custom languages, see K_Creating_Dialects.txt.

=====================================================================
26. TUTORIAL: CROSS-DIALECT DATABASE APPLICATION
=====================================================================

This program uses features from multiple dialects to
create a simple database application:

  10 REM === Cross-Dialect Database ===
  20 DIALECT "BPP"
  30 REM
  40 REM Use QBasic-style structured IF for the menu
  50 REM Use GW-BASIC PRINT USING for reports
  60 REM Use Dartmouth DATA/READ for defaults
  70 REM Use BASIC++ file I/O for persistence
  80 REM
  90 DIM Names$(50), Ages(50), Cities$(50)
  100 Count = 0
  110 REM
  120 REM Load default data (Dartmouth-style)
  130 DATA "Alice", 30, "New York"
  140 DATA "Bob", 25, "Los Angeles"
  150 DATA "Carol", 35, "Chicago"
  160 DATA "", 0, ""
  170 READ N$, A, C$
  180 WHILE N$ <> ""
  190   Count = Count + 1
  200   Names$(Count) = N$
  210   Ages(Count) = A
  220   Cities$(Count) = C$
  230   READ N$, A, C$
  240 WEND
  250 REM
  300 REM === Menu (QBasic-style structured IF) ===
  310 CLS

=====================================================================
30. ADDING FEATURES FROM OTHER LANGUAGES
=====================================================================

Use the dialect + module system to bring features from
other languages into BASIC++:

  FROM PYTHON:
    List comprehensions (simulated via array + FOR loop)
    String formatting (via PRINT USING)
    Dictionary lookup (via parallel arrays)

    Example: Python-like string formatting module
      FMT$("Hello {1}, you are {2} years old", N$, STR$(AGE))
      Implemented as a custom C function that parses {n} placeholders.

  FROM PASCAL:
    REPEAT/UNTIL (already DO/LOOP UNTIL)
    CASE OF (already SELECT CASE)
    Writeln (PRINT with newline — same thing)

    The mapping is nearly 1:1 for structured constructs.

  FROM LOGO:
    Turtle graphics (implementable as a VDev device)
    FORWARD n, RIGHT degrees, LEFT degrees
    PEN UP, PEN DOWN

    Module: mod_turtle.c registers FORWARD(), RIGHT(), LEFT(),
    PENUP(), PENDOWN() as BASIC++ functions.

  FROM FORTH:
    Stack operations (implemented via an array-based stack)
    PUSH X, POP X, DUP, SWAP, ROT

    Module: mod_stack.c provides stack manipulation functions.

  FROM LISP:
    List processing (via linked arrays or string parsing)
    CONS, CAR, CDR (mapped to array operations)

    These are intellectual exercises more than practical tools,
    but they demonstrate the flexibility of the module system.

31. CREATING A SUPERSET DIALECT
=====================================================================

Start with BPP (which is already the union) and ADD more:

  Superset = BPP + your module functions + your aliases

  Example: "BASIC++ Pro" superset

    MODULE "MATHEXT"          ' Extra math functions
    MODULE "FILEUTIL"         ' File utility functions
    MODULE "STRINGEXT"        ' Extra string functions

    ' Now you have BPP + 30 extra functions
    ' This IS your superset dialect

  Another approach: create a boot file (AUTOEXEC.BAS) that
  loads your preferred modules and aliases every time:

    1 REM === AUTOEXEC.BAS ===
    2 REM Loaded automatically at startup
    3 MODULE "MATHEXT"
    4 MODULE "STRINGEXT"
    5 ALIAS "SHOW" "PRINT"
    6 ALIAS "GET" "INPUT"
    7 DIALECT "BPP"
    8 REM Ready for use!

32. BUILDING DSLs (DOMAIN-SPECIFIC LANGUAGES)
=====================================================================

Domain-specific languages are tailored for one task:

  MUSIC DSL:
    TEMPO 120
    TIME 4, 4               ' 4/4 time signature
    NOTE C4, QUARTER
    NOTE E4, QUARTER
    NOTE G4, HALF
    REST QUARTER
    CHORD C4, E4, G4, WHOLE

  DATABASE DSL:
    CONNECT "customers.db"
    SELECT * FROM orders WHERE total > 100
    WHILE NOT DBEOF
      SHOW FIELD$("name"), FIELD$("total")
      ADVANCE
    ENDWHILE
    DISCONNECT

  ROBOT CONTROL DSL:
    MOTOR LEFT, 50           ' 50% speed
    MOTOR RIGHT, 50
    DELAY 2000               ' 2 seconds
    MOTOR LEFT, 0            ' stop
    MOTOR RIGHT, 0
    SENSOR$ = READ_SENSOR(1)

Each DSL is built as:
  1. A dialect config (personality, restricted keywords)
  2. A C module (domain-specific functions)
  3. Aliases (rename keywords to domain terms)
  4. Documentation (the DSL's reference manual)

33. COMBINING DIALECTS WITH VIRTUAL DEVICES
=====================================================================

Dialects control SYNTAX.  VDevs control I/O.
Together they create complete environments:

  Commodore Emulation:
    Dialect "C64B" + VDev "PET:" (PETSCII character set)
    The dialect gives C64 syntax and prompt.
    The VDev translates output to Commodore character codes.

  Spectrum Emulation:
    Dialect "ZXSP" + VDev "ZX:" (Spectrum character set)
    The dialect gives Spectrum syntax and prompt.
    The VDev handles Spectrum-specific I/O.

  Industrial Control:
    Dialect "CTRL" + VDev "SER:" (serial port)
    The dialect provides control keywords.
    The VDev handles RS-232 communication.

34. COMBINING DIALECTS WITH EXTERNAL MODULES
=====================================================================

The most powerful pattern: Dialect + Module + VDev

  Example: Scientific Computing Environment

    Dialect: SCIB (SciBasic)
      - Named variables required
      - Math-focused prompt ("sci> ")
      - All math functions always available

    Module: MATHEXT
      - CUBE, HYPOT, POW, LOG10, LOG2
      - CEIL, FLOOR, ROUND
      - DEG2RAD, RAD2DEG

    Module: MATRIX
      - MAT operations from Dartmouth BASIC
      - Matrix inversion, multiplication, etc.

    VDev: PLOT:
      - Graphical output device
      - Plots data points, curves, histograms

    Usage:
      DIALECT "SCIB"
      MODULE "MATHEXT"
      MODULE "MATRIX"
      DIM A(3,3), B(3,3), C(3,3)
      MAT READ A
      MAT B = INV(A)
      MAT C = A * B
      PRINT "Determinant: "; DET(A)
      PRINT "Eigenvalues computed."

35. PORTABILITY GUIDELINES
=====================================================================

  For MAXIMUM portability across all dialects:

  1. Use LET explicitly: LET A = 5 (ECMA-55 requires it)
  2. Use A-Z variables only (all dialects support A-Z)
  3. Use : for statement separator (all except PATB)
  4. Use <> for not-equal (all except PATB)
  5. Use line numbers (all dialects support them)
  6. Use GOTO/GOSUB (universal across all BASICs)
  7. Use REM (not ') for comments (universal)
  8. Use DIM for arrays (not @())
  9. Avoid WHILE/WEND (not in all dialects)
  10. Avoid SUB/FUNCTION (QBasic only)
  11. Avoid COMPILE/CHAIN/MODULE (BASIC++ only)

  For MAXIMUM features (but BASIC++ only):

  1. Use BPP mode (default)
  2. Use long variable names
  3. Use WHILE/WEND, DO/LOOP
  4. Use modules for extensions
  5. Use file I/O freely
  6. Use COMPILE for native output

36. COMMON PITFALLS AND SOLUTIONS
=====================================================================

  PITFALL: Switching to PATB and using :
    DIALECT "PATB"
    10 PRINT A : PRINT B    ' ERROR: : is not separator in PATB!
    Solution: Use ; in PATB: PRINT A; PRINT B

  PITFALL: Switching to ECMA-55 and omitting LET
    DIALECT "EC55"
    OPTION STRICT
    10 A = 5               ' ERROR: LET required in ECMA-55
    Solution: LET A = 5

  PITFALL: Using # for not-equal outside PATB
    DIALECT "GWBS"
    10 IF A # B THEN...    ' ERROR: # is not <> in GW-BASIC
    Solution: IF A <> B THEN...

  PITFALL: Expecting zone width to stay constant
    DIALECT "GWBS"
    PRINT A, B              ' 14-column zones
    DIALECT "PATB"
    PRINT A, B              ' 8-column zones (different!)
    Solution: Use TAB() for exact column positioning

  PITFALL: Line numbers exceeding dialect range
    DIALECT "PATB"
    50000 PRINT "Hello"     ' ERROR: max is 32767 in PATB
    Solution: Use lines 1-32767, or switch to GWBS (65529)

  PITFALL: Using strings in integer-only dialect
    DIALECT "PATB"
    OPTION STRICT
    A$ = "Hello"            ' ERROR: no string vars in PATB
    Solution: Use a dialect that supports strings
