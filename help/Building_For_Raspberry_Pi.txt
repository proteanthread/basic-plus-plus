1. Overview

Raspberry Pi runs Linux, so BASIC++ compiles and runs exactly like
any other Linux system. No special embedded profile is needed -- the
full interpreter with all 16 dialects and all modules is available.

The Raspberry Pi Pico (RP2040) is a different case -- it is a
microcontroller without an OS, and uses the BPP_EMBEDDED profile.
See section 11 for Pico-specific instructions.


2. Supported Raspberry Pi Models

| Model | CPU | RAM | Status |
|-------|-----|-----|--------|
| Raspberry Pi 5 | BCM2712 (ARM Cortex-A76) | 4-8 GB | Full build |
| Raspberry Pi 4B | BCM2711 (ARM Cortex-A72) | 2-8 GB | Full build |
| Raspberry Pi 3B+ | BCM2837B0 (ARM Cortex-A53) | 1 GB | Full build |
| Raspberry Pi 3B | BCM2837 (ARM Cortex-A53) | 1 GB | Full build |
| Raspberry Pi 2B | BCM2836 (ARM Cortex-A7) | 1 GB | Full build |
| Raspberry Pi 1B+ | BCM2835 (ARM11) | 512 MB | Full build |
| Raspberry Pi Zero 2W | BCM2710A1 (ARM Cortex-A53) | 512 MB | Full build |
| Raspberry Pi Zero W | BCM2835 (ARM11) | 512 MB | Full build |
| Raspberry Pi Pico | RP2040 (ARM Cortex-M0+) | 264 KB | Embedded build |
| Raspberry Pi Pico W | RP2040 (ARM Cortex-M0+) | 264 KB | Embedded build |

All Raspberry Pi models running Raspberry Pi OS (or any Linux) use
the full modern build profile with all features.


3. Quick Build on the Pi

Connect to your Pi via SSH or open a terminal, then:


Install build tools (if not already installed)
sudo apt update
sudo apt install build-essential git

Clone or copy the source
git clone https://github.com/proteanthread/basic-plus-plus.git
cd basic-plus-plus/source

Build with GCC
make

Run
cd ..
./baspp


That is it. The Makefile uses gcc -std=c17 -O2 by default, which
is perfect for Raspberry Pi.

Build time:
- Pi 5 (4 cores): ~3 seconds
- Pi 4 (4 cores): ~5 seconds
- Pi 3 (4 cores): ~8 seconds
- Pi Zero (1 core): ~30 seconds


4. Cross-Compiling from Linux (x86)

If you want to build on a fast Linux desktop and copy the binary to
the Pi:


Install the ARM cross-compiler
sudo apt install gcc-arm-linux-gnueabihf

Build for Raspberry Pi (all models)
cd source
arm-linux-gnueabihf-gcc -std=c17 -O2 -I. \
    core/*.c parser/*.c lexer/*.c flow/*.c io/*.c \
    filemgmt/*.c graphics/*.c variables/*.c arrays/*.c \
    strings/*.c math/*.c functions/*.c struct/*.c \
    errhand/*.c config/*.c debug/*.c help/*.c \
    progmgmt/*.c memory/*.c system/*.c virtual/*.c \
    dialect/*.c modules/*.c codegen/*.c runtime/*.c \
    shell/*.c misc/*.c spec.c \
    -o ../baspp -lm

Copy to the Pi
scp ../baspp pi@raspberrypi.local:~/baspp

SSH in and run
ssh pi@raspberrypi.local
chmod +x baspp
./baspp


For Raspberry Pi 1 / Zero (ARMv6):

Use the armhf compiler with explicit architecture
arm-linux-gnueabihf-gcc -std=c17 -O2 -march=armv6 -mfpu=vfp -mfloat-abi=hard \
    -I. [all source files] -o ../baspp -lm

6. Full Build vs. Minimal Build

On Raspberry Pi (Linux), you almost always want the full build
because you have plenty of RAM and storage.

| Build | Files | Binary Size | RAM Usage | Dialects |
|-------|-------|-------------|-----------|----------|
| Full | 115 | ~400 KB | ~90 MB pools | All 16 |
| Minimal | 36 | ~150 KB | ~20 KB pools | 1 |

A minimal build on the Pi would only make sense for:
- A dedicated single-purpose kiosk
- Running dozens of BASIC++ instances simultaneously
- Intentionally limited teaching environment


7. Memory Budget

The Raspberry Pi has far more memory than needed:

Pi 4 / Pi 5 (4-8 GB RAM)


Total RAM:                        4,096 MB (or 8,192 MB)
Linux kernel + services:           -300 MB
Desktop environment (if used):     -500 MB
Available for applications:      ~3,200 MB

BASIC++ total (full build):          -90 MB
                                  ---------
Remaining free:                  ~3,110 MB


You can safely increase pool sizes for large programs:


// In config.h (modern section):
#define PROGRAM_MEMORY_SIZE   16777216L  // 16 MB
#define MAX_STRING_POOL       67108864L  // 64 MB
#define MAX_ARRAY_ELEMENTS    16777216   // 16M elements (~256 MB)


Pi Zero / Pi 1 (512 MB RAM)


Total RAM:                          512 MB
Linux kernel + services:           -100 MB
Available:                         ~412 MB

BASIC++ (full build):                -90 MB
Remaining:                         ~322 MB  (plenty)


Even the smallest Pi has more than enough for BASIC++.


8. GPIO Access from BASIC

The Raspberry Pi's GPIO pins are accessible via the VDev system.
BASIC++ can control GPIO through Linux's sysfs or libgpiod:

Method 1: Using /sys/class/gpio (works on all Pi models)


' Export GPIO17
OPEN "/sys/class/gpio/export" FOR OUTPUT AS #1
PRINT #1, "17"
CLOSE #1

' Set direction to output
OPEN "/sys/class/gpio/gpio17/direction" FOR OUTPUT AS #1
PRINT #1, "out"
CLOSE #1

' Set HIGH
OPEN "/sys/class/gpio/gpio17/value" FOR OUTPUT AS #1
PRINT #1, "1"
CLOSE #1

' Set LOW
OPEN "/sys/class/gpio/gpio17/value" FOR OUTPUT AS #1
PRINT #1, "0"
CLOSE #1


Method 2: Register a VDev GPIO driver

For convenience, register a VDev driver (see Virtual_Devices.md)
so you can use simple device names:


OPEN "GPIO17:" FOR OUTPUT AS #1
PRINT #1, "1"           ' HIGH
SLEEP 1
PRINT #1, "0"           ' LOW
CLOSE #1



9. I2C and SPI Access

I2C (Inter-Integrated Circuit):

Enable I2C via raspi-config, then access from BASIC:


' Read temperature from I2C sensor
OPEN "/dev/i2c-1" FOR BINARY AS #1
' ... send register address, read response ...
CLOSE #1


For a friendlier interface, register a VDev sensor driver.

SPI (Serial Peripheral Interface):

Enable SPI via raspi-config:

sudo raspi-config
Interface Options > SPI > Enable


Access from BASIC:

OPEN "/dev/spidev0.0" FOR BINARY AS #1
' ... SPI read/write operations ...
CLOSE #1



10. Camera and Display

Camera: Use SHELL to capture images:

SHELL "libcamera-still -o photo.jpg"
' or on older Pi OS:
SHELL "raspistill -o photo.jpg"


HDMI Display: BASIC++ text output goes to the terminal. For
graphical output, the text-mode graphics buffer can be displayed
via the VDev system.


11. Raspberry Pi Pico (RP2040)

The Pico is a microcontroller, NOT a Linux computer. It uses
the BPP_EMBEDDED build profile.

Prerequisites

Install the Pico SDK:

sudo apt install cmake gcc-arm-none-eabi libnewlib-arm-none-eabi
git clone https://github.com/raspberrypi/pico-sdk.git
export PICO_SDK_PATH=~/pico-sdk


Project Structure


pico_basicpp/
  CMakeLists.txt
  main.c
  source/              (copy of BASIC++ source/)


CMakeLists.txt


cmake_minimum_required(VERSION 3.13)
include($ENV{PICO_SDK_PATH}/pico_sdk_init.cmake)

project(basicpp_pico C CXX ASM)
pico_sdk_init()

Collect BASIC++ source files
file(GLOB_RECURSE BPP_SOURCES "source/core/*.c" "source/parser/*.c"
    "source/lexer/*.c" "source/flow/*.c" "source/variables/*.c"
    "source/strings/*.c" "source/math/*.c" "source/functions/*.c"
    "source/dialect/dialect.c" "source/dialect/dialect_patb.c"
    "source/modules/module.c" "source/modules/mod_stdlib.c"
    "source/runtime/*.c" "source/misc/*.c" "source/spec.c")

add_executable(basicpp_pico main.c ${BPP_SOURCES})

target_include_directories(basicpp_pico PRIVATE source)
target_compile_definitions(basicpp_pico PRIVATE BPP_EMBEDDED)
target_link_libraries(basicpp_pico pico_stdlib)

Use USB for stdio (serial console)
pico_enable_stdio_usb(basicpp_pico 1)
pico_enable_stdio_uart(basicpp_pico 0)

pico_add_extra_outputs(basicpp_pico)


main.c


#include "pico/stdlib.h"
#include <stdio.h>
#include "config.h"

extern int basicpp_main(int argc, char **argv);

int main() {
    stdio_init_all();
    sleep_ms(2000);  // Wait for USB serial to connect

    char *argv[] = {"basicpp", NULL};
    basicpp_main(1, argv);
    return 0;
}


Build and Flash


mkdir build && cd build
cmake ..
make -j4

Copy the .uf2 file to the Pico
Hold BOOTSEL button while connecting USB, then:
cp basicpp_pico.uf2 /media/$USER/RPI-RP2/


Pico Memory Budget


Total SRAM:                        264 KB
Pico SDK overhead:                  -20 KB
USB stack:                          -10 KB
Available:                         ~234 KB

BASIC++ pools (BPP_EMBEDDED):       -38 KB
RuntimeState:                       -30 KB
Stack:                               -8 KB
                                    ------
Remaining free:                    ~158 KB



12. Performance Tuning

Optimization flags:

Maximum speed (recommended for Pi 4/5)
gcc -std=c17 -O2 -march=native -I. [files...] -o baspp -lm

Maximum speed with link-time optimization
gcc -std=c17 -O2 -flto -march=native -I. [files...] -o baspp -lm

Minimum binary size (for Pi Zero / embedded)
gcc -std=c17 -Os -I. [files...] -o baspp -lm


Pi-specific flags:

Pi 4 / Pi 5 (64-bit)
gcc -std=c17 -O2 -march=armv8-a -I. [files...] -o baspp -lm

Pi 3 (64-bit)
gcc -std=c17 -O2 -march=armv8-a -mtune=cortex-a53 -I. [files...] -o baspp -lm

Pi Zero / Pi 1 (32-bit)
gcc -std=c17 -O2 -march=armv6 -mfpu=vfp -I. [files...] -o baspp -lm



13. Running as a Service

To start BASIC++ automatically at boot (e.g., for a kiosk):

Create /etc/systemd/system/basicpp.service:

[Unit]
Description=BASIC++ Interpreter
After=multi-user.target

[Service]
ExecStart=/home/pi/baspp
StandardInput=tty
StandardOutput=tty
TTYPath=/dev/tty1
Restart=always
User=pi

[Install]
WantedBy=multi-user.target


Enable and start:

sudo systemctl enable basicpp
sudo systemctl start basicpp



14. Which BASIC Features Work

Everything -- the full build runs on all Pi models:

- All 16 dialects with runtime switching
- All core BASIC statements
- File I/O (read/write any Linux file)
- SHELL / EXEC (run any Linux command)
- SHELL$() (capture command output)
- VDev virtual devices
- GPIO, I2C, SPI access
- Graphics (text-mode buffer)
- Security sandboxing (all 6 levels)
- Dynamic library loading (external .so files)
- Config file system
- Help system
- Debug/trace
- Transpiler/codegen


15. Customizing Pool Sizes for Pi

The default modern profile (~90 MB pools) works fine on all Pi
models. To adjust for specific use cases:

For Pi Zero (512 MB RAM, conservative):

#define MAX_STRING_POOL       1048576L    // 1 MB (was 16 MB)
#define MAX_ARRAY_ELEMENTS    262144      // 256K (was 4M)
// Total: ~12 MB pools


For Pi 5 with 8 GB RAM (maximized):

#define PROGRAM_MEMORY_SIZE   16777216L   // 16 MB
#define MAX_STRING_POOL       67108864L   // 64 MB
#define MAX_ARRAY_ELEMENTS    16777216    // 16M elements (~256 MB)
#define MAX_PROGRAM_LINES     262144      // 256K lines



16. Union Mode on Raspberry Pi

Union Mode is the default on all platforms. On Raspberry Pi, with
all 16 dialects compiled in, you can switch dialects at runtime:


DIALECT "GWBS"     ' Switch to GW-BASIC
DIALECT "C64B"     ' Switch to Commodore 64 BASIC
DIALECT "QBAS"     ' Switch to QBasic
DIALECT LIST       ' Show all available dialects



17. Troubleshooting

"Permission denied" on GPIO
GPIO access requires root or membership in the gpio group:

sudo usermod -aG gpio pi
Log out and back in


Build fails with "cc1: error: unrecognized argument"
Your Pi's GCC version may not support -march=native. Remove
that flag or specify the architecture explicitly.

"Cannot allocate memory"
The Pi has run out of RAM. Close other applications, or reduce
pool sizes in config.h. Check with free -m.

Slow performance on Pi Zero
Use -O2 optimization. The Pi Zero's single ARM11 core is slow
but BASIC++ runs fine for interactive use.

Cross-compiled binary does not run
Check the architecture: file baspp. It should show:

baspp: ELF 32-bit LSB executable, ARM, EABI5

If it shows x86, you compiled with the wrong compiler.
