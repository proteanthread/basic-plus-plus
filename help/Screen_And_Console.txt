THE BASIC++ SCREEN AND CONSOLE SYSTEM
========================================
Version 4.2.3

This manual explains how BASIC++ programs control the
text-mode terminal — cursor positioning, colors, screen
clearing, formatted output, keyboard input, function key
macros, and the screen/width system.

Unlike a quick reference, this manual gives you deep
understanding.  By the time you finish reading it, you will
know:

  - How to position the cursor anywhere on screen
  - How to use all 16 GW-BASIC text colors
  - How PRINT USING formats numbers and strings
  - How TAB, SPC, and the comma/semicolon system work
  - How INKEY$ provides non-blocking keyboard input
  - How function key macros (KEY) work with 48 slots
  - How WIDTH and SCREEN modes configure the display
  - How CSRLIN and POS(0) track the cursor position
  - How to build full-screen text user interfaces
  - How all of this maps to ANSI escape sequences

Part I:  THE TEXT CONSOLE MODEL
======================================================================


1.  OVERVIEW: TERMINAL AS CANVAS
-----------------------------------

BASIC++ treats the terminal as a character grid — a
canvas of rows and columns where each cell holds one
character.  The default grid is:

  80 columns × 25 rows

    Column:  1  2  3  ... 78 79 80
    Row 1:   ┌──┬──┬──   ──┬──┬──┐
    Row 2:   │  │  │       │  │  │
    Row 3:   │  │  │       │  │  │
    ...      │  │  │       │  │  │
    Row 24:  │  │  │       │  │  │
    Row 25:  └──┴──┴──   ──┴──┴──┘

Rows and columns are 1-based:

  - Row 1 is the top of the screen
  - Column 1 is the left edge
  - LOCATE 1, 1 moves to the top-left corner
  - LOCATE 25, 80 moves to the bottom-right corner

This model matches GW-BASIC and QBasic exactly.


2.  ANSI ESCAPE SEQUENCES UNDER THE HOOD
--------------------------------------------

BASIC++ uses ANSI escape sequences for all screen
control.  Every LOCATE, COLOR, and CLS statement
generates standard escape codes:

  Statement            Escape Sequence    Purpose
  ───────────────────  ─────────────────  ──────────────
  CLS                  ESC[2J ESC[H      Clear + home
  HOME                 ESC[H             Cursor home
  LOCATE r, c          ESC[r;cH          Move cursor
  COLOR fg             ESC[SGRm          Set foreground
  COLOR fg, bg         ESC[SGR;SGRm      Set fg + bg
  COLOR (no args)      ESC[0m            Reset colors

ESC = ASCII 27 (hex 1B), also written as \033 in C.

This means BASIC++ works in any terminal that supports
ANSI sequences:

  - Windows Terminal, PowerShell 7, cmd.exe (Win10+)
  - xterm, rxvt, gnome-terminal, konsole (Linux)
  - Terminal.app, iTerm2 (macOS)
  - PuTTY, SSH clients
  - DOS with ANSI.SYS loaded


3.  PLATFORM DIFFERENCES
---------------------------

  Platform   Terminal         ANSI Support
  ─────────  ───────────────  ──────────────────────
  Windows    Windows Terminal Full support
  Windows    cmd.exe (Win10)  Requires VT mode
  Windows    cmd.exe (older)  Needs ANSI.SYS
  Linux      Any terminal     Full support (native)
  macOS      Terminal.app     Full support
  FreeDOS    COMMAND.COM      Needs ANSI.SYS loaded

On Windows, BASIC++ enables VT processing mode at
startup via SetConsoleMode() when compiled with
platform.c.  This enables ANSI escapes in cmd.exe.

On FreeDOS, load ANSI.SYS in CONFIG.SYS:

  DEVICE=C:\DOS\ANSI.SYS


4.  CONSOLE STATE IN RUNTIMESTATE
-------------------------------------

The runtime tracks these console-related fields:

  Field            Type   Default   Purpose
  ───────────────  ─────  ────────  ───────────────────────
  screen_mode      int    0         SCREEN mode (0=text)
  draw_x           int    40        DRAW cursor X
  draw_y           int    25        DRAW cursor Y
  draw_color       int    (pen)     DRAW pen character
  cursor_row       int    1         Current row (CSRLIN)
  cursor_col       int    1         Current col (POS)
  screen_width     int    80        Columns (WIDTH)
  screen_lines     int    25        Rows (WIDTH)
  fkey_macros[]    char   ""        KEY macro strings
  fkey_display     int    0         KEY bar on/off


4b. CONSOLE I/O REDIRECTION (SDL MODE)
-----------------------------------------

All statement parsers, dialect profiles, built-ins, and help
routines MUST include "console.h" and use the redirected output
macros instead of calling raw C standard library functions.

When BASIC++ runs in SDL mode (basicpp.exe / baspp), console
output is routed to the SDL graphical text console buffer.
Direct calls to printf, putchar, or fflush bypass this buffer
and produce invisible output or corruption.

The redirection macros in console.h are:

  Macro               Replaces       Purpose
  ------------------  -------------- ---------------------------------
  printf(...)         gw_printf()    Route to active console buffer
  vprintf(...)        gw_vprintf()   Route variadic output
  fflush(stream)      gw_fflush()    Flush active console buffer
  putchar(c)          gw_console_write_char()  Write single char

These macros are defined in console.h with #define directives.
The guard CONSOLE_C_INTERNAL prevents the macros from replacing
the actual function definitions inside console.c itself.

RULE: Raw printf, putchar, fflush, and vprintf must NEVER be
called directly in statement or command parsers.  Always include
"console.h" and use the macro-redirected versions.

Part II:  SCREEN CONTROL
======================================================================


5.  CLS — CLEAR SCREEN
-------------------------

  Syntax: CLS

Clear the entire screen and move the cursor to row 1,
column 1:

  100 CLS
  110 PRINT "Fresh start!"

CLS routes through the virtual console device's cls
operation, which emits ESC[2J ESC[H.

Use CLS at the beginning of full-screen applications
to ensure a clean display:

  100 CLS
  110 COLOR 15, 1      : REM White on blue
  120 PRINT "╔══════════════════════════════╗"
  130 PRINT "║   My Application v1.0        ║"
  140 PRINT "╚══════════════════════════════╝"


6.  HOME — CURSOR HOME
-------------------------

  Syntax: HOME

Move the cursor to row 1, column 1 WITHOUT clearing the
screen:

  100 HOME
  110 PRINT "I'm at the top!"

HOME emits ESC[H and updates cursor_row and cursor_col
to 1.  Unlike CLS, the existing screen content remains
visible.

Use HOME to overwrite a status line at the top:

  100 HOME
  110 PRINT "Score: "; SCORE%;
  120 PRINT "  Lives: "; LIVES%


7.  LOCATE — POSITION THE CURSOR
------------------------------------

  Syntax: LOCATE row, col

Move the cursor to the specified row and column:

  100 LOCATE 12, 35
  110 PRINT "CENTER!"

  200 LOCATE 1, 1   : PRINT "Top-left"
  210 LOCATE 1, 70  : PRINT "Top-right"
  220 LOCATE 25, 1  : PRINT "Bottom-left"
  230 LOCATE 25, 70 : PRINT "Bottom-right"

Parameters:

  row — vertical position (1 = top, 25 = bottom)
  col — horizontal position (1 = left, 80 = right)

Values less than 1 are clamped to 1.  No maximum is
enforced (your terminal handles overflow).

LOCATE emits ESC[row;colH and updates cursor_row and
cursor_col in the runtime state.

Common patterns:

  REM -- Center text on an 80-column screen --
  100 T$ = "Hello, World!"
  110 COL% = (80 - LEN(T$)) / 2 + 1
  120 LOCATE 12, COL%
  130 PRINT T$

  REM -- Status bar at bottom --
  200 LOCATE 25, 1
  210 PRINT STRING$(80, " ");   : REM clear line
  220 LOCATE 25, 1
  230 PRINT "Press ESC to exit";


8.  CSRLIN — READ CURSOR ROW
-------------------------------

  Syntax: value = CSRLIN

CSRLIN returns the current cursor row (1-based).  It is
a variable-like keyword — no parentheses needed:

  100 LOCATE 15, 1
  110 R% = CSRLIN
  120 PRINT "Cursor is on row "; R%
  130 REM Output: Cursor is on row 15


9.  POS(0) — READ CURSOR COLUMN
-----------------------------------

  Syntax: value = POS(0)

POS returns the current cursor column (1-based).  The
argument (0) is a dummy for GW-BASIC compatibility:

  100 LOCATE 1, 42
  110 C% = POS(0)
  120 PRINT "Cursor is at column "; C%
  130 REM Output: Cursor is at column 42

Use CSRLIN and POS(0) together to save and restore
cursor position:

  100 REM -- Save position --
  110 SAVE_R% = CSRLIN
  120 SAVE_C% = POS(0)
  130 REM -- Do something elsewhere --
  140 LOCATE 25, 1
  150 PRINT "Status update!";
  160 REM -- Restore position --
  170 LOCATE SAVE_R%, SAVE_C%


10.  WIDTH — SET SCREEN DIMENSIONS
--------------------------------------

  Syntax:
    WIDTH columns [, lines]
    WIDTH                        (display current)

Set the logical screen width and optionally the number
of screen lines:

  100 WIDTH 80, 25     : REM Standard 80x25
  110 WIDTH 40         : REM 40-column mode
  120 WIDTH            : REM Print current width

Common modes:

  Mode         Columns   Lines   Use
  ───────────  ────────  ──────  ─────────────────────
  Standard     80        25      Normal text mode
  Wide         132       50      Terminal emulators
  Narrow       40        25      Retro / large text
  Tall         80        50      DOS 80x50 mode

The columns value must be 1-255.  The lines value must
be 1-60.  Values of 40 and 80 are the most common.

WIDTH stores the values in screen_width and screen_lines.
These can be used for formatting:

  100 WIDTH 80, 25
  110 PRINT "Screen: "; screen_width; "x"; screen_lines


11.  SCREEN — SET SCREEN MODE
--------------------------------

  Syntax: SCREEN mode [, color_switch]

Set the display mode.  In BASIC++, screen modes control
the graphics framebuffer:

  Mode  GW-BASIC Meaning       BASIC++ Behavior
  ────  ─────────────────────  ──────────────────────
  0     Text 80×25             Text mode (default)
  1     320×200, 4 colors      Graphics (40×25 canvas)
  2     640×200, 2 colors      Graphics (80×25 canvas)
  7     320×200, 16 colors     Graphics (40×25 canvas)
  8     640×200, 16 colors     Graphics (80×25 canvas)
  9     640×350, 16 colors     Graphics (EGA mode)
  12    640×480, 16 colors     Graphics (VGA mode)
  13    320×200, 256 colors    Graphics (MCGA mode)

Text programs should use SCREEN 0 (the default):

  100 SCREEN 0        : REM text mode
  110 PRINT "Text mode active!"

Graphics programs use SCREEN 1 or higher:

  200 SCREEN 1        : REM 320×200 graphics mode
  210 PSET (160, 100), 15   : REM draw pixel

See Graphics_Sound.txt for full graphics coverage.

Part III:  COLOR AND STYLE

12.  COLOR — SET TEXT COLORS
-------------------------------

  Syntax:
    COLOR fg            Set foreground color
    COLOR fg, bg        Set foreground and background
    COLOR               Reset to default colors

Set the text color for subsequent PRINT output:

  100 COLOR 14         : REM Bright yellow text
  110 PRINT "WARNING: Low battery!"
  120 COLOR            : REM Reset to default


13.  GW-BASIC COLOR PALETTE (0-15)
--------------------------------------

  Code  Name            ANSI FG   ANSI BG
  ────  ──────────────  ────────  ────────
  0     Black           30        40
  1     Blue            34        44
  2     Green           32        42
  3     Cyan            36        46
  4     Red             31        41
  5     Magenta         35        45
  6     Brown/Yellow    33        43
  7     White (light)   37        47
  8     Dark Gray       90        100
  9     Light Blue      94        104
  10    Light Green     92        102
  11    Light Cyan      96        106
  12    Light Red       91        101
  13    Light Magenta   95        105
  14    Yellow          93        103
  15    Bright White    97        107

The first 8 colors (0-7) are the standard palette.
Colors 8-15 are bright/bold versions.


14.  FOREGROUND AND BACKGROUND COLORS
-----------------------------------------

Set both foreground and background:

  100 REM -- White text on blue background --
  110 COLOR 15, 1
  120 PRINT "Classic DOS look!"

  200 REM -- Black text on green background --
  210 COLOR 0, 2
  220 PRINT "Green screen terminal"

  300 REM -- Yellow on red (warning!) --
  310 COLOR 14, 4
  320 PRINT "  DANGER  "

  400 REM -- Create a colored title bar --
  410 COLOR 15, 1          : REM White on blue
  420 LOCATE 1, 1
  430 PRINT STRING$(80, " ");    : REM fill line blue
  440 LOCATE 1, 30
  450 PRINT "MY APPLICATION";
  460 COLOR              : REM Reset colors


15.  RESETTING COLORS
-----------------------

  COLOR (with no arguments) emits ESC[0m, which resets
  all text attributes to terminal defaults:

  100 COLOR 12
  110 PRINT "Red text!"
  120 COLOR
  130 PRINT "Back to normal."

  Always reset colors before your program ends:

  900 COLOR          : REM Reset colors
  910 CLS            : REM Clear screen
  920 END


16.  COLOR AND ANSI SGR CODES
--------------------------------

Under the hood, COLOR maps GW-BASIC codes to ANSI
SGR (Select Graphic Rendition) parameters:

  BASIC Statement      ANSI Sequence
  ───────────────────  ──────────────────────
  COLOR                ESC[0m
  COLOR 7              ESC[37m
  COLOR 15             ESC[97m
  COLOR 15, 1          ESC[97m ESC[44m
  COLOR 0, 7           ESC[30m ESC[47m
  COLOR 14, 4          ESC[93m ESC[41m

Each COLOR call emits one or two ANSI sequences.  The
foreground and background are set independently, so you
can change one without affecting the other:

  100 COLOR 14         : REM Set fg = yellow
  110 PRINT "Yellow text on current background"

Part IV:  OUTPUT FORMATTING
======================================================================


17.  PRINT — THE CORE OUTPUT STATEMENT
-----------------------------------------

PRINT is the most-used statement in BASIC.  It outputs
values to the terminal (or to a file channel):

  100 PRINT "Hello, World!"
  110 PRINT 42
  120 PRINT 3.14159
  130 PRINT A$
  140 PRINT "Score: "; SCORE%

  REM -- PRINT to file channel --
  200 PRINT #1, "Data line"

PRINT ends with a newline by default.  Suppress the
newline with a trailing semicolon:

  100 PRINT "Loading";
  110 FOR I% = 1 TO 10
  120   PRINT ".";
  130   SLEEP 200
  140 NEXT I%
  150 PRINT " Done!"

The # format specifier sets the output width for
numeric values:

  100 PRINT #6 42       : REM Print 42 in 6-char field


18.  SEMICOLONS AND COMMAS IN PRINT
---------------------------------------

Two separators control spacing between PRINT items:

  Separator  Effect
  ─────────  ──────────────────────────────
  ;          No space between items
  ,          Tab to next 14-column zone

Semicolons (compact output):

  100 PRINT "X="; 42; " Y="; 17
  110 REM Output: X=42 Y=17

Commas (tabular output):

  100 PRINT "Name", "Age", "City"
  110 PRINT "Alice", 30, "Denver"
  120 PRINT "Bob", 25, "Portland"

  REM Output:
  REM Name          Age           City
  REM Alice         30            Denver
  REM Bob           25            Portland


19.  TAB(n) — MOVE TO COLUMN
-------------------------------

  Syntax: PRINT TAB(n); expression

TAB moves the print position to column n by emitting
spaces:

  100 PRINT "Name"; TAB(20); "Score"; TAB(35); "Level"
  110 PRINT "Alice"; TAB(20); 9500; TAB(35); 12
  120 PRINT "Bob"; TAB(20); 8200; TAB(35); 10

Output:

  Name               Score          Level
  Alice               9500           12
  Bob                 8200           10

TAB is used inside PRINT statements only.  The argument
is 0-based (TAB(0) is the leftmost position).

Classic game example:

  100 PRINT TAB(33); "STAR TREK"
  110 PRINT TAB(16); "Creative Computing, Morristown, NJ"


20.  SPC(n) — PRINT SPACES
-----------------------------

  Syntax: PRINT SPC(n); expression

SPC prints exactly n spaces:

  100 PRINT "Hello"; SPC(10); "World"
  110 REM Output: Hello          World

The difference between TAB and SPC:

  TAB(n)  moves to an ABSOLUTE column
  SPC(n)  inserts a RELATIVE number of spaces


21.  PRINT USING — FORMATTED OUTPUT
---------------------------------------

  Syntax: PRINT USING "format"; expr [; expr ...]

PRINT USING provides C-printf-like formatted output
using a format string.

21.1  Numeric Format: # and .

= digit placeholder
  . = decimal point

  Examples:

  100 PRINT USING "####"; 42
  110 REM Output:   42

  200 PRINT USING "###.##"; 3.14159
  210 REM Output:  3.14

  300 PRINT USING "##.##"; 1.5
  310 REM Output:  1.50

  400 PRINT USING "$###.##"; 49.99
  410 REM Output: $ 49.99

The field width is the total number of # plus the
decimal point.  Numbers are right-justified within
the field.

21.2  String Format: \ \

  \  \ = string field (width = chars between backslashes)

  Examples:

  100 PRINT USING "\          \"; "Alice"
  110 REM Output: Alice       (padded with spaces)

  200 PRINT USING "\    \"; "Hello, World!"
  210 REM Output: Hello (truncated to fit)

The width of the string field is the number of
characters between the two backslashes, inclusive of
the backslash positions (minimum width = 2).

21.3  Literal Characters

Characters in the format string that are not # . or \
are printed literally:

  100 PRINT USING "Name: \          \  Age: ##"; "Alice"; 30
  110 REM Output: Name: Alice        Age: 30

  200 PRINT USING "[ ## / ## ]"; 5; 20
  210 REM Output: [  5 / 20 ]

21.4  Multiple Values

Separate multiple values with semicolons:

  100 PRINT USING "## + ## = ##"; 3; 5; 8
  110 REM Output:  3 +  5 =  8

  200 FOR I% = 1 TO 5
  210   PRINT USING "Item ##: $###.##"; I%; I% * 9.99
  220 NEXT I%

  REM Output:
  REM Item  1:  $ 9.99
  REM Item  2:  $19.98
  REM Item  3:  $29.97
  REM Item  4:  $39.96
  REM Item  5:  $49.95


22.  WRITE — DATA OUTPUT WITH DELIMITERS
--------------------------------------------

  Syntax: WRITE [#n,] expr [, expr ...]

WRITE outputs values separated by commas, with strings
enclosed in double quotes.  A newline is printed at the
end:

  100 WRITE "Alice", 30, "Denver"
  110 REM Output: "Alice",30,"Denver"

  200 WRITE "Bob", 25, "Portland"
  210 REM Output: "Bob",25,"Portland"

WRITE is ideal for generating CSV-compatible output:

  100 OPEN "data.csv" FOR OUTPUT AS #1
  110 FOR I% = 1 TO 10
  120   WRITE #1, "Record"; I%; I% * 100
  130 NEXT I%
  140 CLOSE #1

WRITE with no arguments prints a blank line.


23.  LPRINT — PRINT TO STDERR
---------------------------------

  Syntax: LPRINT [expr [; expr ...] [;]]

LPRINT works exactly like PRINT but sends output to
stderr instead of stdout.  In GW-BASIC, LPRINT sent
output to the line printer (LPT1:).  In BASIC++,
stderr is the portable equivalent:

  100 PRINT "This goes to stdout"
  110 LPRINT "This goes to stderr"

Use LPRINT for:

  - Diagnostic messages that don't interfere with
    program output
  - Logging (redirect stderr to a file)
  - Separating data output from status messages

Redirect stderr from the command line:

  basicpp myprogram.bas 2>log.txt

Part V:  KEYBOARD INPUT

24.  INPUT — BLOCKING LINE INPUT
------------------------------------

  Syntax: INPUT ["prompt";] var [, var ...]

INPUT displays an optional prompt, waits for the user
to type a response, and stores the result:

  100 INPUT "Enter your name: "; N$
  110 INPUT "Enter your age: "; A%
  120 PRINT "Hello, "; N$; "! You are "; A%; " years old."

Multiple variables can be read with one INPUT:

  200 INPUT "Enter x, y: "; X%, Y%
  210 PRINT "Coordinates: ("; X%; ","; Y%; ")"

INPUT blocks execution until the user presses Enter.


25.  LINE INPUT — READ ENTIRE LINE
--------------------------------------

  Syntax: LINE INPUT ["prompt";] var$

LINE INPUT reads an entire line of text, including
commas and special characters, into a string variable:

  100 LINE INPUT "Enter a sentence: "; S$
  110 PRINT "You typed: "; S$

Unlike INPUT, LINE INPUT does not split on commas:

  INPUT "Text: "; S$      REM "a,b,c" splits into 3
  LINE INPUT "Text: "; S$  REM "a,b,c" stored as-is

LINE INPUT can also read from files:

  100 OPEN "data.txt" FOR INPUT AS #1
  110 LINE INPUT #1, L$
  120 PRINT L$
  130 CLOSE #1


26.  INKEY$ — NON-BLOCKING KEY READ
---------------------------------------

  Syntax: K$ = INKEY$

INKEY$ checks the keyboard buffer and returns:

  - A 1-character string if a key was pressed
  - An empty string ("") if no key is waiting

INKEY$ does NOT wait — it returns immediately:

  100 PRINT "Press any key (or ESC to exit)..."
  110 DO
  120   K$ = INKEY$
  130   IF LEN(K$) > 0 THEN
  140     PRINT "You pressed: "; K$;
  150     PRINT " (ASCII "; ASC(K$); ")"
  160   END IF
  170 LOOP UNTIL K$ = CHR$(27)

INKEY$ is essential for game loops and interactive
programs that need to check for input without stopping.


27.  BUILDING A KEY EVENT LOOP
---------------------------------

The standard game-loop pattern:

  100 REM ======================================
  110 REM  Game Loop with INKEY$
  120 REM ======================================
  130 CLS
  140 X% = 40 : Y% = 12  : REM Player position
  150 DO
  160   K$ = INKEY$
  170   IF K$ <> "" THEN
  180     SELECT CASE K$
  190       CASE "w", "W"
  200         IF Y% > 1 THEN Y% = Y% - 1
  210       CASE "s", "S"
  220         IF Y% < 25 THEN Y% = Y% + 1
  230       CASE "a", "A"
  240         IF X% > 1 THEN X% = X% - 1
  250       CASE "d", "D"
  260         IF X% < 80 THEN X% = X% + 1
  270       CASE CHR$(27)
  280         EXIT DO
  290     END SELECT
  300   END IF
  310   REM -- Draw --
  320   CLS
  330   LOCATE Y%, X%
  340   PRINT "@";
  350   LOCATE 25, 1
  360   PRINT "WASD=move  ESC=quit  X:";X%;" Y:";Y%;
  370   SLEEP 33       : REM ~30 FPS
  380 LOOP
  390 CLS
  400 END


28.  SPECIAL KEYS AND KEY CODES
-----------------------------------

Common ASCII codes returned by INKEY$:

  Key         ASC()   CHR$()
  ──────────  ──────  ──────────
  Enter       13      CHR$(13)
  Escape      27      CHR$(27)
  Space       32      CHR$(32)
  Backspace   8       CHR$(8)
  Tab         9       CHR$(9)
  Delete      127     CHR$(127)

Letter keys return their ASCII code:

  Key   ASC()   Key   ASC()
  ────  ──────  ────  ──────
  A     65      a     97
  B     66      b     98
  Z     90      z     122
  0     48      9     57

Arrow keys and function keys generate multi-byte
escape sequences.  INKEY$ returns the first byte
(ESC = 27), and subsequent calls return the remaining
bytes.  For simple programs, check the first byte:

  100 K$ = INKEY$
  110 IF ASC(K$) = 27 THEN
  120   REM Possible arrow key or ESC
  130   K2$ = INKEY$
  140   IF K2$ = "[" THEN
  150     K3$ = INKEY$
  160     IF K3$ = "A" THEN PRINT "Up arrow"
  170     IF K3$ = "B" THEN PRINT "Down arrow"
  180     IF K3$ = "C" THEN PRINT "Right arrow"
  190     IF K3$ = "D" THEN PRINT "Left arrow"
  200   ELSE
  210     PRINT "Escape pressed"
  220   END IF
  230 END IF

29.  WHAT ARE FUNCTION KEY MACROS?
-------------------------------------

GW-BASIC allowed you to assign text strings to the
function keys (F1-F12).  Pressing F1 would type the
assigned text into the keyboard buffer, as if the user
had typed it manually.

BASIC++ preserves this system with 48 macro slots:

  Slots 1-12:   F1 through F12
  Slots 13-24:  SHIFT+F1 through SHIFT+F12
  Slots 25-36:  CTRL+F1 through CTRL+F12
  Slots 37-48:  ALT+F1 through ALT+F12

Each slot holds up to 15 characters (FKEY_MAX_LEN = 15).


30.  KEY n, string$ — ASSIGN A MACRO
----------------------------------------

  Syntax: KEY slot, "text"

Assign a string to a function key slot:

  100 KEY 1, "RUN" + CHR$(13)    : REM F1 = RUN + Enter
  110 KEY 2, "LIST" + CHR$(13)   : REM F2 = LIST + Enter
  120 KEY 3, "SAVE" + CHR$(13)   : REM F3 = SAVE + Enter
  130 KEY 4, "LOAD" + CHR$(13)   : REM F4 = LOAD + Enter
  140 KEY 5, "CONT" + CHR$(13)   : REM F5 = CONT + Enter

The slot number must be 1-48.  The string is stored in
the fkey_macros[] array in RuntimeState.

Custom macros for a game:

  100 KEY 1, "NORTH" + CHR$(13)
  110 KEY 2, "SOUTH" + CHR$(13)
  120 KEY 3, "EAST" + CHR$(13)
  130 KEY 4, "WEST" + CHR$(13)
  140 KEY 5, "LOOK" + CHR$(13)


31.  KEY ON / KEY OFF — DISPLAY BAR
---------------------------------------

  Syntax:
    KEY ON      Show the function key bar
    KEY OFF     Hide the function key bar

KEY ON displays the GW-BASIC-style function key bar at
the bottom of the screen.  This shows the first 6
characters of each F1-F10 macro:

  100 KEY 1, "HELP"
  110 KEY 2, "LOAD"
  120 KEY 3, "RUN"
  130 KEY ON

Output:

  1HELP  2LOAD  3RUN   4      5      6      7      8      9      10

KEY OFF hides the bar:

  200 KEY OFF


32.  KEY LIST — SHOW ALL ASSIGNMENTS
----------------------------------------

  Syntax: KEY LIST

Display all non-empty key assignments:

  100 KEY 1, "HELP"
  110 KEY 2, "LOAD"
  120 KEY 10, "QUIT"
  130 KEY 25, "CTRL-SAVE"
  140 KEY LIST

Output:

  KEY  1  F1   "HELP"
  KEY  2  F2   "LOAD"
  KEY 10  F10  "QUIT"
  KEY 25  CTRL+F1  "CTRL-SAVE"


33.  SLOT LAYOUT (48 SLOTS)
------------------------------

  Slot   Modifier    Function Key
  ─────  ──────────  ────────────
  1-12   (none)      F1-F12
  13-24  SHIFT+      F1-F12
  25-36  CTRL+       F1-F12
  37-48  ALT+        F1-F12

The group is calculated as: group = (slot - 1) / 12

  Group 0: slots 1-12   = F1-F12
  Group 1: slots 13-24  = SHIFT+F1-SHIFT+F12
  Group 2: slots 25-36  = CTRL+F1-CTRL+F12
  Group 3: slots 37-48  = ALT+F1-ALT+F12

The function key within a group: fn = (slot - 1) % 12 + 1


34.  KEY(n) ON/OFF/STOP — EVENT TRAPPING
--------------------------------------------

  Syntax:
    KEY(n) ON     Enable key event trapping
    KEY(n) OFF    Disable key event trapping
    KEY(n) STOP   Suspend key event trapping

These statements control key event trapping (used with
ON KEY(n) GOSUB).  Currently consumed but not fully
implemented — included for GW-BASIC source compatibility.

35.  BEEP — AUDIBLE ALERT
----------------------------

  Syntax: BEEP

Emit an audible beep:

  100 BEEP
  110 PRINT "Alert!"

Platform implementation:

  Platform   Method
  ─────────  ────────────────────────────
  Windows    Beep(800, 200) via kernel32
  Linux      Terminal bell (BEL char)
  FreeDOS    PC speaker (BEL char)


36.  BEEP ON / BEEP OFF — ERROR BEEP
----------------------------------------

  Syntax:
    BEEP ON      Enable error beep (default)
    BEEP OFF     Disable error beep

Control whether errors produce an audible beep:

  100 BEEP OFF        : REM Silence error beeps
  200 BEEP ON         : REM Re-enable error beeps


37.  SOUND — PLAY A TONE
---------------------------

  Syntax: SOUND frequency, duration

Play a tone at the given frequency (Hz) for the given
duration (in clock ticks at 18.2 ticks/second):

  100 SOUND 440, 18   : REM A4 for ~1 second
  110 SOUND 880, 9    : REM A5 for ~0.5 seconds
  120 SOUND 0, 18     : REM silence for 1 second

Duration conversion:

  ticks × 55 ≈ milliseconds
  1 second ≈ 18.2 ticks
  0.5 seconds ≈ 9 ticks

Common frequencies:

  Note   Freq (Hz)     Note   Freq (Hz)
  ─────  ──────────    ─────  ──────────
  C4     262           G4     392
  D4     294           A4     440
  E4     330           B4     494
  F4     349           C5     523


38.  PLAY — MUSIC MACRO LANGUAGE (OVERVIEW)
----------------------------------------------

  Syntax: PLAY string$

PLAY uses the GW-BASIC music macro language — a compact
string notation for melodies:

  100 PLAY "CDEFGAB"          : REM C major scale
  110 PLAY "O4 L4 CDEF"      : REM octave 4, quarter notes
  120 PLAY "T120 L8 CDEFEDC"  : REM tempo 120, eighth notes

PLAY commands:

  Command   Description
  ────────  ─────────────────────────────
  C-B       Play note (C, D, E, F, G, A, B)
or +    Sharp
  -         Flat
  O0-O6     Set octave (default O4)
  >         Octave up
  <         Octave down
  L1-L64    Set note length (1=whole, 4=quarter)
  T32-T255  Set tempo in BPM (default T120)
  Pn        Pause for length n
  Nn        Play note by number (0-84)
  .         Dotted note (1.5× length)

See Graphics_Sound.txt for full PLAY documentation.

39.  EXAMPLE: FULL-SCREEN MENU SYSTEM
-----------------------------------------

  100 REM ======================================
  110 REM  Full-Screen Menu System
  120 REM ======================================
  130 SEL% = 1    : REM Currently selected item
  140 NITEMS% = 5 : REM Number of menu items
  150 ITEMS$(1) = "New Game"
  160 ITEMS$(2) = "Load Game"
  170 ITEMS$(3) = "Settings"
  180 ITEMS$(4) = "High Scores"
  190 ITEMS$(5) = "Exit"
  200 REM
  210 DO
  220   CLS
  230   COLOR 15, 1
  240   LOCATE 1, 1
  250   PRINT STRING$(80, " ");
  260   LOCATE 1, 30
  270   PRINT "MAIN MENU";
  280   COLOR
  290   REM
  300   FOR I% = 1 TO NITEMS%
  310     LOCATE 8 + I% * 2, 30
  320     IF I% = SEL% THEN
  330       COLOR 0, 15  : REM Highlight: black on white
  340       PRINT " > "; ITEMS$(I%); " ";
  350       COLOR
  360     ELSE
  370       COLOR 7
  380       PRINT "   "; ITEMS$(I%)
  390       COLOR
  400     END IF
  410   NEXT I%
  420   REM
  430   LOCATE 23, 25
  440   COLOR 8
  450   PRINT "Use W/S to navigate, Enter to select"
  460   COLOR
  470   REM
  480   K$ = ""
  490   DO : K$ = INKEY$ : LOOP UNTIL K$ <> ""
  500   SELECT CASE K$
  510     CASE "w", "W"
  520       SEL% = SEL% - 1
  530       IF SEL% < 1 THEN SEL% = NITEMS%
  540     CASE "s", "S"
  550       SEL% = SEL% + 1
  560       IF SEL% > NITEMS% THEN SEL% = 1
  570     CASE CHR$(13)
  580       IF SEL% = 5 THEN GOTO 700
  590       CLS
  600       PRINT "You selected: "; ITEMS$(SEL%)
  610       PRINT "Press any key..."
  620       DO : LOOP UNTIL INKEY$ <> ""
  630   END SELECT
  640 LOOP
  700 CLS
  710 COLOR
  720 PRINT "Goodbye!"
  730 END

43.  EXAMPLE: CONSOLE GAME FRAMEWORK
-----------------------------------------

  100 REM ======================================
  110 REM  Console Game Framework
  120 REM ======================================
  130 REM
  140 REM -- Game state --
  150 PX% = 40 : PY% = 12  : REM player
  160 SCORE% = 0
  170 LIVES% = 3
  180 FRAME% = 0
  190 CLS
  200 REM
  210 REM -- Function key setup --
  220 KEY 1, "HELP"
  230 KEY 2, "SAVE"
  240 KEY ON
  250 REM
  260 REM -- Main game loop --
  270 DO
  280   FRAME% = FRAME% + 1
  290   REM
  300   REM -- Input --
  310   K$ = INKEY$
  320   IF K$ = "w" OR K$ = "W" THEN
  330     IF PY% > 2 THEN PY% = PY% - 1
  340   END IF
  350   IF K$ = "s" OR K$ = "S" THEN
  360     IF PY% < 23 THEN PY% = PY% + 1
  370   END IF
  380   IF K$ = "a" OR K$ = "A" THEN
  390     IF PX% > 1 THEN PX% = PX% - 1
  400   END IF
  410   IF K$ = "d" OR K$ = "D" THEN
  420     IF PX% < 79 THEN PX% = PX% + 1
  430   END IF
  440   IF K$ = " " THEN
  450     SCORE% = SCORE% + 10
  460     BEEP
  470   END IF
  480   IF K$ = CHR$(27) THEN EXIT DO
  490   REM
  500   REM -- Draw --
  510   CLS
  520   REM Title bar
  530   COLOR 15, 1
  540   LOCATE 1, 1
  550   PRINT STRING$(80, " ");
  560   LOCATE 1, 5
  570   PRINT "Score: "; SCORE%;
  580   LOCATE 1, 30
  590   PRINT "GAME";
  600   LOCATE 1, 60
  610   PRINT "Lives: "; LIVES%;
  620   COLOR
  630   REM Player
  640   COLOR 14
  650   LOCATE PY%, PX%
  660   PRINT "@";
  670   COLOR
  680   REM Footer
  690   COLOR 8
  700   LOCATE 25, 1
  710   PRINT "WASD=move SPACE=score ESC=quit";
  720   PRINT TAB(60); "Frame:"; FRAME%;
  730   COLOR
  740   REM
  750   SLEEP 33  : REM ~30 FPS
  760 LOOP
  770 REM
  780 REM -- Game over --
  790 CLS
  800 COLOR
  810 LOCATE 12, 30
  820 PRINT "GAME OVER"
  830 LOCATE 14, 28
  840 PRINT "Final Score: "; SCORE%
  850 LOCATE 25, 25
  860 PRINT "Press any key to exit."

  880 CLS
  890 END

48.  TROUBLESHOOTING
----------------------

  Problem: Colors don't display, garbage text appears
  Fix:     Terminal doesn't support ANSI escapes.
           - Windows: Use Windows Terminal or enable
             VT mode with: REG ADD HKCU\Console
             /v VirtualTerminalLevel /t REG_DWORD /d 1
           - FreeDOS: Load ANSI.SYS in CONFIG.SYS
           - SSH: Use a VT100-compatible client

  Problem: LOCATE doesn't position correctly
  Fix:     Rows/columns are 1-based.
           LOCATE 0, 0 is invalid; use LOCATE 1, 1.
           Check terminal window size matches WIDTH.

  Problem: INKEY$ never returns anything
  Fix:     Terminal may be in cooked/canonical mode.
           BASIC++ uses platform.c to set raw mode
           at startup.  Verify platform_init() ran.

  Problem: CLS doesn't clear the scrollback buffer
  Fix:     CLS clears the visible screen only. This
           is standard ANSI behavior. Use ESC[3J for
           scrollback clear (not all terminals support).

  Problem: KEY ON bar doesn't appear
  Fix:     Assign at least one key macro first:
           KEY 1, "HELP" : KEY ON

  Problem: PRINT USING shows wrong width
  Fix:     Count all # symbols (including those after
           the decimal point) plus the . itself.
           "###.##" = 6 characters wide.
