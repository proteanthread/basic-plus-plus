1. OPENING FILES

OPEN associates a storage resource or virtual device with a numbered channel
(1 through 16 by default, expandable via configuration). The statement
specifies the filename, operational access mode, and channel number:

    OPEN "DATA.TXT" FOR INPUT AS #1
    OPEN "OUTPUT.TXT" FOR OUTPUT AS #2
    OPEN "LOG.TXT" FOR APPEND AS #3
    OPEN "RECORDS.DAT" FOR RANDOM AS #4 LEN = 128
    OPEN "RAW.BIN" FOR BINARY AS #5

* INPUT Mode: Opens an existing file for sequential reading from the
  beginning. If the file is not found, Error 53 occurs.
* OUTPUT Mode: Creates a new file or overwrites an existing file for
  sequential writing from the beginning.
* APPEND Mode: Opens an existing file for writing at the end, preserving
  existing contents. If the file does not exist, it is created.
* RANDOM Mode: Opens a file for fixed-length record access. The optional
  LEN = rlen clause defines the record size in bytes (default 128 bytes).
  Records are 1-indexed.
* BINARY Mode: Opens a file for unformatted byte-level access without record
  framing.

FREEFILE returns the lowest available unallocated channel number:

    F% = FREEFILE
    OPEN "CONFIG.DAT" FOR INPUT AS #F%

2. SEQUENTIAL FILE READING

INPUT #n, var1 [, var2, ...] reads comma-delimited tokens from channel n:

    10 OPEN "VALUES.CSV" FOR INPUT AS #1
    20 WHILE NOT EOF(1)
    30   INPUT #1, Item$, Quantity%, Price
    40   PRINT Item$, Quantity%, Price
    50 WEND
    60 CLOSE #1

LINE INPUT #n, strvar$ reads an entire line up to the terminating newline into
a string variable, preserving whitespace and internal commas:

    10 OPEN "LOG.TXT" FOR INPUT AS #1
    20 WHILE NOT EOF(1)
    30   LINE INPUT #1, LineBuffer$
    40   PRINT LineBuffer$
    50 WEND
    60 CLOSE #1

EOF(n) returns true (-1) when the read pointer reaches the end of the file, or
false (0) if more data remains.

3. SEQUENTIAL FILE WRITING

PRINT #n, [expr1 [;|, expr2 ...]] writes formatted text representations to
channel n, using identical delimiter rules to standard screen PRINT:

    10 OPEN "REPORT.TXT" FOR OUTPUT AS #1
    20 PRINT #1, "Date: "; DATE$; " Time: "; TIME$
    30 PRINT #1, "Total Count: "; TotalCount%
    40 CLOSE #1

WRITE #n, expr1 [, expr2, ...] outputs comma-separated values, automatically
enclosing strings in quotes and suppressing leading spaces on positive
numbers, suitable for CSV ingestion.

4. RANDOM ACCESS FILES

Random-access files utilize fixed-width sector buffers managed via FIELD:

    10 OPEN "CUSTOMERS.DAT" FOR RANDOM AS #1 LEN = 64
    20 FIELD #1, 4 AS CustID$, 30 AS Name$, 30 AS City$
    30 LSET CustID$ = MKI$(1001)
    40 LSET Name$ = "Jane Doe"
    50 LSET City$ = "San Francisco"
    60 PUT #1, 1               ' Write record 1
    70 GET #1, 1               ' Read record 1
    80 PRINT CVI(CustID$), RTRIM$(Name$), RTRIM$(City$)
    90 CLOSE #1

* FIELD #n, width AS var$ [, ...]: Maps string variables directly into the
  channel's sector buffer without allocating separate string descriptors.
* LSET var$ = expr$: Left-justifies a string into a fielded buffer variable,
  padding with trailing spaces or truncating if too long.
* RSET var$ = expr$: Right-justifies a string into a fielded buffer variable,
  padding with leading spaces.
* PUT #n [, record_number]: Flushes the buffer to the specified record number
  (1-indexed).
* GET #n [, record_number]: Reads the specified record into the buffer.
* LOC(n): Returns the current record number.
* LOF(n): Returns the total file length in bytes.

5. BINARY FILE I/O

Binary files permit direct reading and writing of arbitrary byte slices:

    10 OPEN "IMAGE.BIN" FOR BINARY AS #1
    20 Buffer$ = SPACE$(256)
    30 GET #1, 1, Buffer$      ' Read 256 bytes starting at byte 1
    40 PUT #1, 1025, Buffer$   ' Write 256 bytes starting at byte 1025
    50 CLOSE #1

* SEEK #n, position: Moves the file pointer to the specified 1-based byte
  offset.
* SEEK(n): Returns the current 1-based byte position of the file pointer.

6. FILE MANAGEMENT STATEMENTS

* CLOSE [#n1 [, #n2, ...]]: Flushes buffers and closes specified channels.
  CLOSE with no arguments closes all open channels.
* RESET: Flushes all buffers and closes all active file channels.
* KILL filespec$: Deletes the designated file from storage.
* NAME oldname$ AS newname$: Renames an existing file.
* FILES [pattern$]: Lists directory contents matching an optional wildcard
  specification.

7. DIRECTORY MANAGEMENT

* CHDIR path$: Changes the current working directory.
* MKDIR path$: Creates a new subdirectory.
* RMDIR path$: Removes an empty subdirectory.
* CURDIR$: System variable returning the absolute path of the current
  directory.
