# CWD$

## 1. Syntax & Parameters
`CWD$`

**Parameters:** None.

## 2. Description & Usage
The `CWD$` built-in string function returns the name of the current working directory. Unlike `PWD$`, which returns the complete absolute path, `CWD$` isolates and returns only the final directory component (the current folder name).

This keyword is particularly useful when building dynamic user interfaces or prompts that need to display the current folder context without cluttering the screen with a long absolute path. It functions similarly to the `basename` utility found in Unix environments.

## 3. Code Examples
```basic
10 ' Display the current folder name
20 PRINT "You are currently in the folder: "; CWD$
30 ' Example of using it dynamically
40 CUR_DIR$ = CWD$
50 IF CUR_DIR$ = "tests" THEN PRINT "Running from tests directory."
```

## 5. Implementation Details
During expression parsing in `parser_expr.c`, `CWD$` invokes the underlying C standard library function `_getcwd` (on Windows) or `getcwd` (on POSIX systems) to retrieve the full absolute path into a 512-byte buffer. The interpreter then scans this buffer from left to right, looking for path separators (`/` or `\`). 

It updates a pointer (`last_comp`) to point to the character immediately following the last detected separator. This isolates the final directory name. The isolated string is then stored in the interpreter's string pool (`strpool_store`), and a `BValue` representing this string is pushed onto the evaluation stack.

If `getcwd` fails, an empty string is returned. The length of the string is bounded by the underlying OS maximum path length (usually 260 or 4096 bytes depending on the platform), but it fits safely within the allocated 512-byte buffer limit for paths in this implementation.

## 6. Cross-References / See Also
- `PWD$`: Returns the full absolute path.
- `CURDIR$`: An alias that returns the current folder name but with a trailing slash/backslash.
- `CHDIR`: Changes the current working directory.
- `MKDIR`: Creates a new directory.

## 7. Historical Context
Classic interpreters like GW-BASIC did not have a built-in function solely dedicated to extracting the current folder name as a distinct string (`CWD$`). Users had to manually manipulate environment variables or perform string slicing (using `RIGHT$`, `INSTR`, etc.) on the result of a path query. BASIC++ introduces `CWD$` as a modern convenience to adhere to more robust scripting capabilities.
