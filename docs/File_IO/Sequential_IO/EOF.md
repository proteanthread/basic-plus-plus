# EOF

## 1. Syntax & Parameters
`status = EOF(channel)`
- `channel`: The numeric file handle assigned during the `OPEN` statement (e.g., 1 to 255).

## 2. Description & Usage
Returns `-1` (True) if the end of a sequential file has been reached, or `0` (False) if there is still data remaining to be read. It is fundamentally used within loops (`WHILE NOT EOF(1)`) to iteratively parse lines of data until a file is fully consumed.

## 3. Code Examples
```basic
10 OPEN "I", 1, "DATA.TXT"
20 WHILE NOT EOF(1)
30   LINE INPUT #1, L$
40   PRINT L$
50 WEND
60 CLOSE 1
```

## 4. Internal C-Source Mapping
- Function: `builtin_eof` in `source/io/builtins_fileio.c`
- Registration: `builtins.c` under `KW_EOF`

## 5. Implementation Details
The VM checks the internal state flag of the C standard library `feof()` or the VFS stream offset against the total file length.
**Edge Cases & Boundary Conditions:**
- If the `channel` is not currently open, calling `EOF(channel)` triggers Error 52 `Bad file number`.
- For `OUTPUT` mode files, `EOF()` will inherently always return `-1` since you are at the end of the newly created stream.
- **Troubleshooting**: If your loop runs infinitely, ensure you are actually executing a `READ` or `LINE INPUT` command inside the loop to advance the internal file pointer!

## 6. Cross-References / See Also

## 7. Historical Context
`EOF` behaves identically to the classic GW-BASIC and standard ECMA-116 specifications. It remains a staple of sequential file processing.

## 8. Manual Testing Guide
**Interactive Test:**
1. Launch `basicpp-console.exe`.
2. Type `OPEN "O", 1, "test.tmp": PRINT #1, "X": CLOSE 1`
3. Type `OPEN "I", 1, "test.tmp": PRINT EOF(1): LINE INPUT #1, A$: PRINT EOF(1): CLOSE 1`
4. Verify the first `PRINT` is `0` and the second is `-1`.

**Scripted Test (.BAS):**
```basic
10 OPEN "O", 1, "eof.tmp"
20 PRINT #1, "DATA"
30 CLOSE 1
40 OPEN "I", 1, "eof.tmp"
50 WHILE NOT EOF(1)
60   INPUT #1, A$
70 WEND
80 PRINT "REACHED END OF FILE SUCCESSFULLY."
90 CLOSE 1
100 KILL "eof.tmp"
```
