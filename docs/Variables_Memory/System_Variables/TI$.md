# TI$

## 1. Syntax & Parameters
```basic
TI$
TI$ = <string_expression>
```
**Parameters**:
- (None / System Defined) or specific arguments as noted above.

## 2. Description & Usage
The TI$ system variable returns a 6-character string representing the time elapsed since boot or since it was last reset, formatted as "HHMMSS". It can also be assigned a string to reset the internal tick counter relative to a specific time.
Usage scenarios include execution timing, random seed initialization, calendar calculations, and strictly emulating historical time behaviors across different dialects.

## 3. Code Examples
```basic
10 TI$ = "000000" ' Reset timer
20 PRINT "Elapsed time: "; TI$
```

## 5. Implementation Details
Recognized in lexer.c as KW_TI_FUNC (`TI$`). It translates the internal tick counter (`TI`) into a 24-hour string format "HHMMSS" without colons. Ensure that string allocation is safe and string pool garbage collection can handle frequent TI$ polling inside tight loops.
**Troubleshooting**: If execution yields a syntax error or a type mismatch, ensure the dialect parser explicitly supports the token in `parser_expr.c`. Memory allocation issues during string polling (for `$` variants) will trigger an OOM panic.

## 7. Historical Context
Another staple from Commodore BASIC. Unlike TIME$, TI$ does not include colons and is tied to the internal uptime rather than the real-time clock, though some implementations sync them. Our engine decouples them appropriately.
