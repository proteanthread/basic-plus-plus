# TIME

## 1. Syntax & Parameters
```basic
TIME
TIME = <numeric_expression>
```
**Parameters**:
- (None / System Defined) or specific arguments as noted above.

## 2. Description & Usage
The TIME system variable provides a numeric representation of the current system time. When read, it returns a precise float or long integer reflecting the seconds since midnight or an encoded numeric format depending on the active dialect. When used as an assignment, it attempts to set the internal or system clock to the specified numeric value.
Usage scenarios include execution timing, random seed initialization, calendar calculations, and strictly emulating historical time behaviors across different dialects.

## 3. Code Examples
```basic
10 T = TIME
20 PRINT "Current numeric time:"; T
30 TIME = 36000 ' Set time to 10:00:00 AM (if supported)
```

In the lexer, 'TIME' is recognized as KW_TIME (DFLAG_ALL). In parser_expr.c, this keyword will map to an internal time query. Currently, numeric time reads and writes may trigger ERR_SYNTAX or fallback evaluation unless explicitly handled in parser_flow.c. Mutations to this variable should update the virtual hardware clock or OS clock (subject to security policies).
**Troubleshooting**: If execution yields a syntax error or a type mismatch, ensure the dialect parser explicitly supports the token in `parser_expr.c`. Memory allocation issues during string polling (for `$` variants) will trigger an OOM panic.

## 7. Historical Context
In traditional BASIC (like QBasic), TIME was rarely numeric (mostly TIME$ was used). ECMA-116 and full standard BASIC sometimes implement a numeric TIME function returning seconds since midnight (like TIMER in QB). We support it for broad dialect compatibility.
