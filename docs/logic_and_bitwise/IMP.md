# IMP

## 1. Syntax & Parameters
Result = Expression1 IMP Expression2 
*(Note: For NOT, syntax is Result = NOT Expression1)*

- Expression1: A numeric or relational expression.
- Expression2: A numeric or relational expression (Not applicable for NOT).

## 2. Description & Usage
The IMP (implication) operator evaluates to false only if the first expression is true and the second expression is false; otherwise, it evaluates to true. For numeric values, it performs a bitwise implication, which is logically equivalent to (NOT A) OR B on a bit-by-bit basis.

## 3. Code Examples
**Bitwise Example:**
`asic
PRINT 5 IMP 3
' Output: -3
' Explanation: 
' NOT 5 is -6 (...1111 1010). 
' 3 is (...0000 0011). 
' -6 OR 3 is (...1111 1011), which is -3.
`

**Logical Example:**
`asic
A = 1
B = 2
IF (A=1) IMP (B=1) THEN
    PRINT "True"
ELSE
    PRINT "False"
END IF
' Output: False
' First expression is True (-1), second is False (0). (NOT -1) OR 0 is 0 OR 0 = 0 (False).
`

## 4. Internal C-Source Mapping
Implemented in: parser_expr.c (Handling OP_IMP inside the expression parsing and evaluation loop).

## 5. Implementation Details
In parser_expr.c, IMP is mapped to OP_IMP. The operation is implemented on integers using the logic: ~(left) | right. The operands are acquired via bval_to_int(). Ensure that unary NOT precedence is applied correctly inside the macro/function evaluating IMP.

## 6. Cross-References / See Also
AND, OR, NOT, XOR, EQV

## 7. Historical Context
Found in GW-BASIC and QBASIC for logical implication. It is the least commonly used logical operator but required for ECMA-116 and legacy code parity.

## 8. Manual Testing Guide
To verify IMP manually:
1. Open terminal and launch asicpp-console.exe.
2. Enter PRINT 5 IMP 3 and verify the bitwise result.
3. Write a small script testing logical truths:
`asic
10 A = -1
20 B = 0
30 PRINT A IMP B
40 END
`
4. Run the script and verify the expected logical outcome.
5. Exit using SYSTEM.

### 11. Abstract Syntax Tree (AST) Life Cycle
During the parsing phase, the Recursive Descent Parser encounters the token associated with this keyword. It allocates an `AST_Node` structure from the `AST_ARENA` and populates its operand pointers. At runtime, the `ast_interpreter.c` engine performs a post-order traversal to evaluate all child expression nodes before triggering the final execution hook. This two-pass system guarantees that syntax errors (like mismatched parentheses or missing commas) are caught globally before any destructive side-effects occur. Once parsed, the `AST_Node` resides in memory until `NEW` or `RUN` is executed, at which point the entire arena is zeroed out to prevent memory leaks.

To prevent regressions across builds (Windows, Linux, or MCU), the execution of this keyword is entirely deterministic. It behaves identically regardless of the endianness of the host CPU (Little-Endian x64 vs Big-Endian legacy chips). For developers writing performance-critical algorithms in BASIC++, be aware that calling this keyword inside a `FOR...NEXT` or `WHILE...WEND` loop incurs a minimal virtual dispatch overhead.
