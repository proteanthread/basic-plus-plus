# ON ERROR GOTO

### 1. Syntax & Parameters
`ON ERROR GOTO <line_number | label | 0>`

*   **`line_number`**: An integer literal representing the line number to branch to when an error occurs.
*   **`label`**: An alphanumeric label to branch to.
*   **`0`**: A special argument that disables error trapping completely.

### 2. Description & Usage
The `ON ERROR GOTO` statement enables global runtime error trapping in a BASIC++ program. When enabled, any subsequent runtime exception (such as Division by Zero, File Not Found, or an explicit `ERROR` statement) will not halt the program. Instead, execution will unconditionally branch to the specified line number or label.

**Usage:**
Once branched to the error handler, the program is considered to be in an "error state." Inside the handler, the `ERR` and `ERL` variables can be inspected to determine the cause and location of the fault. The handler *must* conclude with a `RESUME` statement to clear the error state and return to normal execution. Calling `ON ERROR GOTO 0` disables trapping; any subsequent error will cause the program to crash/halt normally.

**Edge Cases & Boundary Conditions:**
*   **Errors Inside the Handler:** If another runtime error occurs *while already inside* the error handling routine (before a `RESUME` is executed), the program will immediately halt. Error trapping is temporarily suspended while inside the handler to prevent infinite recursive error loops.
*   **Missing Target:** If the target `line_number` or `label` does not exist, an `ERR_UNDEFINED_LINE` or `ERR_UNDEFINED_LABEL` exception is thrown during parsing or runtime.
*   **Scope:** `ON ERROR GOTO` is global. The most recently executed `ON ERROR GOTO` statement overrides any previous ones.

### 3. Code Examples

**Basic Error Handler:**
```basic
10 ON ERROR GOTO ErrorHandler
20 X = 10 / 0
30 PRINT "This will not print initially."
40 END
ErrorHandler:
50 PRINT "Caught an error!"
60 RESUME NEXT
```

**Disabling Error Trapping:**
```basic
10 ON ERROR GOTO 100
20 ON ERROR GOTO 0
30 ERROR 11 ' This will halt the program immediately.
40 END
100 PRINT "This will never be reached."
110 RESUME NEXT
```

### 5. Implementation Details
The Lexer identifies the tokens `KW_ON`, `KW_ERROR`, and `KW_GOTO` in sequence.

**Parser Expectations:**
The parser maps the target parameter and validates its syntactic correctness. If `0` is passed, it creates an AST node specifically flagged to clear the handler.

**Struct Mutations:**
*   **`vm->on_error_target`**: A pointer to the AST node representing the error handler. Set to `NULL` if `ON ERROR GOTO 0` is executed.
*   **`vm->in_error_handler`**: A boolean flag set to `true` when execution jumps to the handler. Cleared to `false` when `RESUME` is executed.

**Execution Paths & Error Handling:**
1. Upon executing `ON ERROR GOTO target`, the VM links the AST node of `target` to `vm->on_error_target`.
2. When a runtime error occurs (`vm_throw_error`), the VM checks if `vm->on_error_target` is not `NULL` and `vm->in_error_handler` is `false`.
3. If true, `vm->error_code` and `vm->error_line` are populated, `vm->in_error_handler` is set to `true`, and `vm->pc` jumps to the target.
4. If `vm->in_error_handler` is already `true` (an error within an error), the VM initiates a fatal halt.

**What to do if it breaks:**
If errors are not being trapped, verify that `vm->on_error_target` is properly persisted across execution contexts. If the program infinite-loops on an error, ensure `vm->in_error_handler` is strictly enforced to block re-entrancy into the handler.

### 7. Historical Context
`ON ERROR GOTO` is the quintessential exception-handling mechanism of 8-bit and 16-bit BASIC dialects. While modern architectures favor localized `TRY...CATCH` blocks, global error traps remain powerful for monolithic state machines and are fully supported in BASIC++ to satisfy strict ECMA-116 and GW-BASIC requirements.

### 11. Abstract Syntax Tree (AST) Life Cycle
During the parsing phase, the Recursive Descent Parser encounters the token associated with this keyword. It allocates an `AST_Node` structure from the `AST_ARENA` and populates its operand pointers. At runtime, the `ast_interpreter.c` engine performs a post-order traversal to evaluate all child expression nodes before triggering the final execution hook. This two-pass system guarantees that syntax errors (like mismatched parentheses or missing commas) are caught globally before any destructive side-effects occur. Once parsed, the `AST_Node` resides in memory until `NEW` or `RUN` is executed, at which point the entire arena is zeroed out to prevent memory leaks.

### 14. Performance Profiling & Optimization Rules
For developers writing performance-critical algorithms in BASIC++, be aware that calling this keyword inside a `FOR...NEXT` or `WHILE...WEND` loop incurs a minimal virtual dispatch overhead. Because the interpreter uses a switch-case dispatch engine in `exec.c`, the branch predictor on modern CPUs will optimize repeated calls. However, on 8-bit or 16-bit chips, minimizing the use of string-mutating variants of this keyword will drastically improve frame rates and execution speed.
