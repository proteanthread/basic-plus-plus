# SPACE$

## 1. Syntax & Parameters
`SPACE$(n)`

*   **`n`**: A numeric expression denoting the number of space characters (ASCII 32) to generate. Must evaluate between 0 and 255.

## 2. Description & Usage
The `SPACE$` function returns a string consisting entirely of space characters. It is primarily used for text formatting, padding, alignment, and clearing specific sections of a console screen. 

If the provided length `n` is less than 0, it is automatically clamped to 0 (resulting in an empty string). If `n` is greater than 255, it is strictly clamped to a maximum limit of 255 spaces. This safety limit ensures predictable memory consumption and guards against runaway allocation attacks or bugs.

## 3. Code Examples

**Basic Formatting:**
```basic
10 PRINT "LEFT" + SPACE$(10) + "RIGHT"
```
*Output:*
```text
LEFT          RIGHT
```

**Variable Padding:**
```basic
10 N = 5
20 PAD$ = SPACE$(N)
30 PRINT "*" + PAD$ + "*"
```
*Output:*
```text
*     *
```

**Clamping Demonstration:**
```basic
10 REM Attempt to create 500 spaces
20 BIG$ = SPACE$(500)
30 PRINT LEN(BIG$)
```
*Output:*
```text
255
```

## 5. Implementation Details
The `SPACE$` keyword invokes `builtin_space`. 
1.  **Parsing & Clamping:** The function first extracts the argument using `bval_to_int(&args[0])`. It explicitly checks boundary conditions: `if (n < 0) n = 0; if (n > 255) n = 255;`. This hardcoded constraint prevents extreme memory requests.
2.  **Memory Allocation:** It attempts to allocate the requested size `n` from the global runtime string pool via `strpool_alloc(&state->strpool, n)`. 
3.  **Execution Path:** If `strpool_alloc` returns `NULL` (indicating pool exhaustion), the function immediately bails out and returns a null/empty `bval_string(NULL, 0)`. If successful, it performs a fast `for` loop filling the buffer with `' '` (ASCII 32) characters.
4.  **Struct Mutation:** Finally, it wraps the newly filled buffer into a `BValue` struct using `bval_string(buf, n)` and returns it to the evaluator.

## 7. Historical Context
`SPACE$` is heavily inspired by GW-BASIC and QBASIC, where it was standard practice to use it for string padding. The hardcoded 255-character limit is a direct homage to the 8-bit lineage of Microsoft BASICs, where strings physically could not exceed 255 bytes in length. Even though BASIC++ operates on 64-bit systems, this semantic constraint is preserved for strict compatibility.
