# CHR$

## 1. Syntax & Parameters
`CHR$(n)`

*   **`n`**: A numeric expression representing the ASCII character code (0 to 255). If `n` evaluates to a floating-point number, it will be implicitly truncated/converted to an integer.

## 2. Description & Usage
The `CHR$` function converts a given ASCII character code (a numeric value) into a single-character string representation. It is the exact inverse of the `ASC` function. `CHR$` is extremely useful for inserting unprintable or control characters (such as carriage returns, line feeds, tabs, or escape sequences) into string variables or output streams. 

If the value passed to `CHR$` falls outside the standard 8-bit ASCII range (0-255), the behavior depends on the underlying integer conversion and truncation mechanisms of the BASIC++ value system. In standard usage, it maps strictly to the 0-255 ASCII/Extended ASCII set.

## 3. Code Examples

**Basic Usage:**
```basic
10 PRINT "Hello" + CHR$(32) + "World"
20 A$ = CHR$(65)
30 PRINT A$
```
*Output:*
```text
Hello World
A
```

**Using Control Characters:**
```basic
10 REM Print a string with a carriage return and line feed
20 MSG$ = "Line 1" + CHR$(13) + CHR$(10) + "Line 2"
30 PRINT MSG$
```

**Looping through ASCII codes:**
```basic
10 FOR I = 65 TO 90
20 PRINT CHR$(I);
30 NEXT I
```
*Output:*
```text
ABCDEFGHIJKLMNOPQRSTUVWXYZ
```

## 5. Implementation Details
The `CHR$` function is implemented natively in C via `builtin_chr`. 
1.  **Execution Path:** When invoked, the function extracts the execution state from `rt` (to access the string pool). It then delegates the logic to `bval_chr(&args[0], 0, &state->strpool)`.
2.  **Memory Bounds & String Pool:** Creating a new string requires allocating exactly 1 byte (plus any internal string metadata/null-terminator overhead) from the managed string pool (`state->strpool`). If the string pool is exhausted, the allocation will fail, and it will return a null string (or raise an `ERR_SORRY` internally based on `bval_chr` implementation).
3.  **Boundary Conditions:** Values are cast to their corresponding integer values. If the argument passed is floating-point, it will undergo implicit type conversion. The character generation maps strictly to the low byte of the resulting integer.
