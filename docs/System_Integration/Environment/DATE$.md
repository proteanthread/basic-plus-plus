# DATE$

## 1. Syntax & Parameters
`DATE$`

- **Parameters**: None.
- **Return Type**: String (Format: `MM-DD-YYYY`)

## 2. Description & Usage
The `DATE$` system variable returns the current system date as a string formatted as `MM-DD-YYYY`. 
It is a read-only system variable that retrieves the calendar date at the exact moment of evaluation. 
This is widely used in legacy BASIC applications for scheduling, daily reporting, and calendar-based logic. 
The string length is strictly 10 characters, ensuring predictable formatting for string slicing and layout manipulation.

## 3. Code Examples
```basic
10 PRINT "Today's date is: "; DATE$
20 M$ = LEFT$(DATE$, 2)
30 D$ = MID$(DATE$, 4, 2)
40 Y$ = RIGHT$(DATE$, 4)
50 PRINT "Year: "; Y$; " Month: "; M$; " Day: "; D$
```

## 5. Implementation Details
In `parser_expr.c` (around line 1334), `KW_DATE_FUNC` invokes the C standard library's `time()` and `localtime()` APIs. 
It writes into a local stack buffer using `sprintf(buf, "%02d-%02d-%04d", tm->tm_mon + 1, tm->tm_mday, tm->tm_year + 1900)`. 
The result is precisely 10 bytes long. This string is stored in the garbage-collected string pool (`strpool_store`), and a string value is pushed onto the interpreter's evaluation stack (`val_stack`).

The implementation assumes the host OS provides accurate local time representation. The year output uses 4 digits (e.g., 2026), preventing Y2K-like truncation issues inherent in some legacy BASIC systems that returned two-digit years.

## 7. Historical Context
In GW-BASIC and QBASIC, `DATE$` was both a function and a statement (e.g., `DATE$ = "10-25-1995"`). In BASIC++, setting the system date via `DATE$` requires specific environmental permissions and is typically restricted or treated as read-only depending on the operating system, but reading it via `DATE$` remains fully backward compatible.
