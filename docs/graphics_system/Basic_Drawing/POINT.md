# POINT

## 1. Syntax & Parameters
`color_index = POINT(x, y)`
- `x`: The horizontal screen coordinate.
- `y`: The vertical screen coordinate.

## 2. Description & Usage
Returns the color attribute of the pixel located at the specified `(x, y)` coordinates on the active graphical screen or virtual framebuffer. If the coordinates are outside the current view port, it returns `-1`.

## 3. Code Examples
```basic
10 SCREEN 13
20 PSET (100, 100), 15
30 C = POINT(100, 100)
40 IF C = 15 THEN PRINT "White pixel found!"
```

## 4. Internal C-Source Mapping
- Function: `builtin_point` in `source/graphics/builtins_gfx.c`
- Registration: `builtins.c` under `KW_POINT`

## 5. Implementation Details
It reads directly from the SDL2 surface lock or the virtual memory-mapped VRAM buffer depending on the current subsystem backend.
**Edge Cases & Boundary Conditions:**
- **Boundary Violation**: Querying `x` or `y` coordinates that exceed the current `SCREEN` resolution (e.g., `POINT(9999, 9999)`) will not cause an out-of-bounds segfault; it safely triggers `-1`.
- **Text Mode Error**: Calling `POINT` while in standard text mode (`SCREEN 0`) will immediately trigger an `Illegal function call` error.
- **Troubleshooting**: If the color returned does not match expectations, ensure that a `WINDOW` or `VIEW` coordinate translation is not implicitly skewing your `x, y` inputs.

## 6. Cross-References / See Also

## 7. Historical Context
Identical to GW-BASIC and QBASIC. Used heavily in older 8-bit collision detection algorithms where reading the screen buffer was faster than calculating hitboxes.
